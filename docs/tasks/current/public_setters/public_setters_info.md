# Публичные сеттеры и поля

## Контекст

Вынесено из второго этапа аудита (`docs/audits/2026-11-02_client_stage2.md`), пункт P6. Правило: `ARCHITECTURE_PRINCIPLES.md` P6, данные меняются только через методы, исключение: `[MemoryPackable]`.

Подсчёт аудита от 2026-11-01 устарел: 81 публичный сеттер (3 в тестах) и 459 кандидатов на публичное изменяемое поле (201 в тестах и генераторе), больше всего в `client/core/Editor` (34 и 186). Считалось по шаблону, поэтому туда вошли сериализуемые данные редактора и `[Serializable]`. После этого изменилось правило для `[MemoryPackable]`, а часть кода удалена. Менять API можно, такой коммит помечается `BREAKING:`.

## Что сделать

1. Пересчитать и разделить на группы: настоящие нарушения, `[MemoryPackable]`, поля, которых требует `JsonUtility` или `[Serializable]`, тесты и исходники генератора.
2. Для `JsonUtility` и `[Serializable]` решить общий способ: `[SerializeField] private` с геттером либо записанное исключение.
3. Исправлять по одной группе на коммит, начиная с runtime.

Критерий готовности: новый подсчёт без настоящих нарушений; исключения записаны в правиле; все тесты проходят.

## Примеры

`client/core/Editor/Catalogues/Assets/AssetCatalogGenerator.cs` (`AssetGroupDefinition`, `AssetPropertyDefinition`), `client/core/Editor/Catalogues/Audio/AudioCatalogMetadata.cs:14`, `client/core/Runtime/Options/PlatformOptions.cs` (`PlatformType`, сеттер для окна настроек), `client/modules/settings/Runtime/SettingsSave.cs` (`JsonUtility`).

## Решения оркестратора (по инвентаризации `public_setters_inventory.md`)

1. **`public` внутри `internal`-типа считается нарушением:** правило говорит «нигде», такой член виден всей сборке.
2. **D1 `SettingsSave`:** `{ get; private set; }` и метод. Ключ JSON `<Name>k__BackingField` не меняется, сохранения игроков не ломаются.
3. **D2 записи каталогов в YAML:** `[SerializeField] private _name`, геттер, `[FormerlySerializedAs("Name")]`, правка строковых ключей `FindPropertyRelative`. Перед правкой EditMode-тест на чтение старых ассетов. Если тест покажет, что старые ассеты не читаются, шаг останавливается.
4. **D3 JSON-модели, которые читает и пишет только `JsonUtility`:** записанное исключение. Имена полей здесь и есть формат файла. Условие исключения: `[Serializable]`, без логики, сериализуется только `JsonUtility`.
5. **Записанные исключения:** `[MemoryPackable]`, D3, Blazor `[Parameter]`, именованный аргумент атрибута, `override` чужого публичного свойства. Другие исключения не добавляются без записи здесь.
6. **Генератор (F2) и тесты (F1) чинятся, исключения нет:** правило прямо включает тесты. Генератор идёт последним и согласуется с параллельной задачей `file_splits`, которая режет те же файлы.
7. **Stored-состояния E2:** `init`, где значение не меняется, иначе `private set` с `[JsonProperty]`. Сначала тест загрузки из JSON на старом коде. Редакторы консоли с `@bind="Value.X"` переводятся без исключения из правила.
8. **`FileLoggerOptions`:** `init`, потому что `ConfigurationBinder` молча теряет `private set`.
9. **Игры не правятся в этой задаче.** Коммит, меняющий API, помечается `BREAKING:` и говорит, что должны изменить игры.
