### Находки и решения (неочевидное, тупики и почему)
- Архив читается лениво: монтирование читает заголовок+оглавление; блоки, которые никто не грузит, могут быть нулями; дописывать блоки
  в смонтированный файл можно (проверено в редакторе Linux; на WebGL MEMFS не проверено — первое, что проверить на стенде).
- Порядок движка в архиве неудобен (файлы меню по всему архиву): `UseArchive` «как есть» не проходит критерий; свой порядок через
  `ArchiveAndCompress` — штатный формат движка, не свои пачки.
- Type tree = 2/3 байтов rc3 (29 → 10.9 MB per-file br; 41 → 15.6 MB LZ4-архив). Даже без архива `DisableWriteTypeTree` сам по себе
  почти вдвое уменьшает байты rc3 — но не число запросов.
- Фиксированные страницы (Cache API по странице) — хуже по байтам меню в 3–8 раз: отвергнуто.
- Оглавление архива 381 KB (сжато) на старте — цена схемы; индекс без хэш-имён станет меньше json rc3 (файл = два числа).
- `DisableWriteTypeTree` риск: контент и плеер обязаны совпадать по сериализации типов — так и есть (одна сборка); тесты PlayMode
  регистрируют каталог в редакторе — те же типы.
- Нули архива на вебе: 15 MB вместо ~300 MB raw нулей у rc3 (MEMFS выделяет память под `SetLength`) — побочный выигрыш.
