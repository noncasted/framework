### Находки и решения (неочевидное, тупики и почему)
- **Cache API игнорирует фрагмент URL** при `match` (exclude fragment flag): ключ `<url>#<offset>` из брифа склеил бы все записи; взят
  `<url>?offset=<n>`. `KeepOnly` сравнивает URL без query (оставляет записи текущих `<hash>.archive` и индекса).
- Диапазон из кэша берётся, только если в кэше все файлы диапазона (иначе весь диапазон из сети) — просто и покрывает оба сценария
  (первое открытие / повторное той же сборки).
- Файлы, целиком попавшие в склеенный диапазон (зазор), тоже становятся real и кэшируются — повторных запросов за ними нет.
- Header архива — псевдофайл `ContentIndex.Header` (`"header"`, `[0, HeaderLength)`), идёт одним диапазоном с манифестом и корнями
  (порядок архива): регистрация = 1 запрос (PlayMode это проверяет).
- В тестах `CopyContentRangeSource.Pin` восстанавливает `LastWriteTimeUtc` — как веб; LocalStore с `<hash>.index.json` внутри папки
  регистрируется (PlayMode), отдельной папки для индекса не нужно.
- Preloaded WebGL: индекс не в `.data`, а файлом StreamingAssets (fetch по URL) — не проверено ни на одной игре (в доках помечено).
- Плеер больше не держит индекс в Resources (только `ContentStamp`), индекс качается при старте — +1 запрос и время до регистрации.
