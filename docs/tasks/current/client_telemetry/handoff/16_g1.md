## Что сделано (с evidence)

### Разведка точки входа загрузок
Общая точка есть, нового API для игры не нужно: все группы каталогов (аудио, спрайты, префабы, env-ассеты) грузятся через
`AssetGroup.Load` (`core/Runtime/Catalogues/Shared/AssetGroup.cs`), сцены скоупов через `ServiceScopeSceneLoader.Load`. В Pixel Swarm
(только чтение) прямых `Addressables.Load*` в `client/Assets` нет; музыка забега — `MusicRunAudio.Group` через `RequestAudioGroup`
(`GamePlay/Services/Sounds/SoundsScopeExtensions.cs`), т.е. её загрузка теперь видна. Для игр, грузящих в обход, есть
`AssetLoads.Begin(key)` ... `Finish()` / `Fail(e)` (шаг в `releases/unreleased.md`).

### Загрузки в сессии
- core: `AssetLoads.Started` / `Ended` (EventSource, исключения слушателей не ломают загрузку), `Running`; ключ из кода:
  `Group: <Name>`, `Scene: <name>` (до загрузки сцены — `Scene`, имя сцены по ссылке неизвестно до загрузки).
- telemetry: `AssetLoadTelemetryCollector` (live + sample): метки `load.start`, `load.end` (длительность), `load.failed`
  (`<ключ> (<тип исключения>)`, длительность), `load.slow` (один раз, на сэмпле после `slowLoadSeconds`, по умолчанию 5 с),
  `load.unfinished` (в конце сессии, время до сих пор). Загрузка, начатая до сессии, отслеживается без метки старта.
- Метки идут с `Detail` и `DurationMs` (контракт расширен, сервер скрабит detail, режет до 128).

### Страница до Unity
- `client/modules/telemetry/WebTemplate~/startup-trace.js`: `window.startupTrace.begin/end/mark/read` на `performance.now()`,
  без зависимостей, ошибки глотаются, не больше 256 спанов, `setResourceTimingBufferSize(1000)`.
- Как скрипт попадает в шаблон: **никак в шаблон**. `Editor/TelemetryStartupTraceInjection` (`IPostprocessBuildWithReport`,
  WebGL) вставляет его первым в `<head>` собранного `index.html` (`<script data-startup-trace>`). Файлы игры не пишутся, путь
  берётся из `report.summary.outputPath`, правило 1 соблюдено; страница с маркером не трогается; без `<head>` сборка падает.
  Работает и для `WebGlBuild`, и для сборки из меню. Шаблону остаётся только вызывать `startupTrace.*`.
- `Runtime/Page/TelemetryPageTimeline.jslib`: Navigation Timing, Resource Timing (имя файла = последний сегмент пути, схема,
  хост, query и hash отрезаются в JS), спаны `startupTrace`. Не читает `location.href` (тест приватности).
- `TelemetryPageSpans.Build`: корень `Page` (0 = `performance.timeOrigin`): `Navigation` (Redirect/DNS/Connect/Request/Response),
  `Document` (до DOMContentLoaded — тут блокирующий `telegram-web-app.js` в `<head>`), `Load event`, `Files` → `File` с `File`,
  `TransferBytes`, `Cached` (тело не пришло или пришли только заголовки 304), `Build start` (от конца последнего файла до старта
  C#: компиляция wasm, запуск инстанса), спаны шаблона с вложенностью; открытые закрываются на старте C# и `Unfinished`.
- Склейка часов: в момент отправки страница даёт `performance.now()`, трейс — время от своего начала (`Profiler.StartTimestamp`,
  Stopwatch), старт C# = разность. Спаны сборки сдвигаются на него, `DurationMs` трейса считается от начала страницы.
  Вне веба `NoTelemetryPageTimeline` → трейс как раньше. Трейс уходит после авторизации, адрес прежний.
