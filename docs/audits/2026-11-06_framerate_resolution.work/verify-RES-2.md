### RES-2 CONFIRMED
- Severity: minor (was minor)
- Evidence: run
- Why: `pixelRatio` picks `limited = min(ceil(device/maxRatio - eps), floor(visibleSide/360 + eps))` and returns `device / max(1, limited)` (`render-resolution.js:95,97`), so k is *from* `device/maxRatio` upwards (ceil, the smallest whole k with the ratio at most maxRatio), the exact opposite of the header's "low takes k up to device / maxRatio" (`:9`), which can only mean k ≤ device/maxRatio and hence a ratio *above* maxRatio. A node run of the shipped file reproduces the code side: 895x393 CSS at 2.75 with maxRatio 1 gives ratio 0.916667, k 3.000 against device/maxRatio 2.750 (the header's own "820x360" example, and the pinned test expectation `2.75d / 3d`), and maxRatio 2 gives ratio 1.375, at most maxRatio — a game author reading the sentence would set a tag expecting "never below maxRatio" and get the reverse. The same header's second clause ("as the largest k that still leaves the visible short side ... at least 360") is also false once the ratio bound binds: 800 CSS wide at device 2, maxRatio 1 renders k 2 (ratio 1), while the largest k keeping the short side ≥ 360 would be 4. The `?dpr` sentence (`:18-19`, "replaces maxRatio of the low resolution") is likewise wrong about scope: a numeric `?dpr` assigns `maxRatio` before the `else if (isHigh())` short-circuit (`:84-85`), so Android `auto` (= high) with `?dpr=2` renders 1.375, not 2.75, as the run and test `:38` show.
- Lines: `client/modules/resolution/WebTemplate~/render-resolution.js:9` - "low takes k up to device / maxRatio", an upper bound on k, while k is the smallest integer above that value

- Fix check: the direction rewording and the `?dpr` scope statement are right and needed, but the proposed text "the smallest k that keeps the render ratio at most maxRatio and the visible short side at least 360" is not what the code does on a narrow canvas: `min` of the two bounds means the 360 bound wins there and the ratio goes above maxRatio (run: 1.375 with maxRatio 1; test `:51`). Better: "low takes the smallest k with device / k at most maxRatio (k from device / maxRatio up); when that would leave the visible short side under 360 canvas pixels, the largest k that keeps it at 360, the ratio then exceeding maxRatio; `?dpr=<number>` replaces maxRatio in every mode, so it caps High too, `?dpr=native` keeps the device ratio."
