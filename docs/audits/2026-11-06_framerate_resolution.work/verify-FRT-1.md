### FRT-1 FALSE
- Severity: minor (was minor)
- Evidence: reading
- Why: The finding's premise — that installing the markers mid-frame makes the `End` marker of *that same* frame run with the unchanged `_started` — contradicts Unity's documented behaviour of `PlayerLoop.SetPlayerLoop` (Unity 6000.0 and 7000.0): "The new update order does not take effect until the next full Player loop iteration, but the changes are immediately visible in subsequent calls to `PlayerLoop.GetCurrentPlayerLoop`." The frame in which `Run` executes therefore still runs the *old* loop, which has no `FrameWorkMeter` markers at all on a first installation, so neither `Begin` nor `End` runs that frame; `LastWorkMs` stays at the `0` that `Run` wrote. From the next iteration on, `Begin` (index 0 of `EarlyUpdate`) and `End` (last of `PostLateUpdate`) are part of the same loop and always run in pairs, `Begin` first, so `End` never subtracts a stale/zero `_started`. The first `OnUpdate` (MonoBehaviour `Update`, between them) is the fresh rule's very first `Feed`, which `AutoFrameRateRule` discards (`_hasFrame == false` -> `Restart`, `return false`), so even the `0` left by `Run` is not counted as a frame; the following `OnUpdate` already reads a genuine `End` value. The re-entry half is refuted independently: `Run` is reached from `_setting.FrameRate.View(lifetime, Choose)` with the scope lifetime, so the markers are not removed when the mode leaves Auto and `_started` is refreshed by that frame's `Begin` before any `End`; if `Run` is called between an `End` and the next `Begin`, the published loop change again only applies from the next iteration, whose `Begin` precedes its `End`. Consequently the uptime-sized value the finding describes is never written to `LastWorkMs` nor fed to the rule. (A different, unclaimed hazard exists: `With` silently inserts nothing if a custom loop lacks `EarlyUpdate`/`PostLateUpdate`, which would let `End` run unpaired — but that is not the reported scenario and does not occur with Unity's default loop.)

If hardening is wanted, it belongs in `With` (fail fast when `EarlyUpdate` or `PostLateUpdate` is absent instead of installing only one of the two markers), which is a different finding.
