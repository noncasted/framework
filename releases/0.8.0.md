# 0.8.0

56 commits (`v0.7.0..75f3909c`, 3 of them merges of the branch `no-addressables`). The main thing: Addressables removed, the content after the start is engine
bundles (`ContentBundle`, Scriptable Build Pipeline, `IContentLoader`, `ContentReference<T>` / `ContentScene`), the catalogues on them; almost
everything is BREAKING for the client. Also: the core without uGUI and without `Framework.Shared` (`Internal.UGUI`, `StableHash` in `Framework.Common`,
`Internal.EncodedAudio`), the client telemetry over HTTP (`AddHttpClientTelemetry`, `MapClientTelemetryHttpIntake`) with the socket transport in
`Internal.Telemetry.Socket`, the layouts in the package `layout`, `LocalizedLabel` in `Internal.Localization.Tmp`, a lambda root of a scope is the error
`CINGR017`.

The intermediate scheme of content directories (`v0.7.0-rc.*`: `ExtraContent`, `AddContentDirectory`, the archive and Range requests, the index) is not in the
release: a game on `v0.7.0` does not need it, the steps lead from Addressables straight to the bundles. The notes for `v0.7.0-rc.*` in steps 1 and 8 are only for
a game that was on that line.

## Steps

Search everywhere from the root of the game. No matches: the step is skipped. Steps 1-8 are content, 9-15 the client assemblies, 16 the test scripts.

Content order. The Addressables fork is no longer in `tools/framework/client/packages`, so together with the pointer remove Addressables
from the manifest at once (step 5), then bring the code to compile (steps 2-4), Regenerate All (step 3), the `ContentBundle` assets (step 1), the references (step 4),
`AddressableAssetsData` last. The values of the `AssetReference` fields do not carry over by themselves: write them down before the change
(`grep -rn "m_AssetGUID" client/Assets --include='*.asset' --include='*.prefab' --include='*.unity'`; after an asset is resaved
the old value is in `git show <before the update>:<file>`). The model and the API: `.claude/docs/CONTENT.md`.

### 1. Content: `ContentBundle` assets, a player build builds the bundles (BREAKING)

Who: the client of every game. The content after the start (the groups of the catalogues, the scenes of scopes, own lazy references) is engine bundles
(`com.unity.modules.assetbundle`), built by the Scriptable Build Pipeline (`com.unity.scriptablebuildpipeline` 4.0.1) with every
player build. Any player build (`Internal.WebGlBuild.Build`, `deploy-client`, the build window, `-build*Player`) builds every
`ContentBundle` asset of the project (`ContentBuild`: an `IPlayerBuildStep` and a `BuildPlayerProcessor`); `WebGlBuild` no longer calls
`SharedAddressablesSync.Sync()`.

Search: `grep -rl "04fd5fef2205f8906860bb0e1ce60ce7" client/Assets --include='*.asset'` (the GUID of the `ContentBundle` script; empty - the step is needed).

Do:
- Create > Framework > Content Bundle - the main bundle; the name of the asset = the name of the bundle = `ContentOptions.Name` (step 2), letters, digits, `_`,
  `-`. The root is the generated `<ContentFolder>/Runtime/Catalogues/ContentRoot.asset` (step 3). `IsPreloaded` - the bundle in the `.data` of
  WebGL (no requests, a bigger first load); `IsGzip` - the WebGL player downloads `<file>.gz` and unpacks it on the page.
- The main bundle (and every bundle of `AddContentBundle`) loads whole and is held until the end of the root scope. A bundle holds its roots
  and everything they reach by direct and lazy references, except the roots of other bundles: without other bundles all the catalogue groups go
  in the main one and load at the start. The heavy things (level groups, music, scenes) are roots of separate `ContentBundle` bundles: they
  load on the lifetime of the load and unload after it, and the main one is kept thin.
- The build fails on a root of two bundles, on an asset that two bundles reach directly and that is assigned to none (make
  it a root of one of them or of a shared bundle), on a lazy target without a root that two bundles reach, on an empty or broken lazy
  reference, on a reference to a child object of a prefab.
- `Assets/FrameworkContentStamp` in the `.gitignore` of the game: the catalog of the bundles (`Resources/Content/catalog.json`) is written there for the time of the build
  and deleted after it (it stays only if the editor crashed in the middle of a build).
- Remove `WithoutAddressables`, `SharedCommonPaths`, `GroupPhases` from `ProjectSettings/Framework.json` (extra keys are ignored).
  The sections `Content` / `ExtraContent` (only in games on `v0.7.0-rc.*`) are an editor error: for every directory a `ContentBundle` asset
  with its `Roots` and `IsPreloaded` (`IsArchiveGzip` -> `IsGzip`).

Check: the build logs `[ContentBuild] N content bundles for <target>: ...` and `[ContentBuild] <name>: ...` for every bundle (files,
bytes, how the player gets it, dependencies, roots, the assets the engine copied inside; a warning about built-in resources);
the `StreamingAssets/Content` of the build holds only `<name>.<hash>.bundle[.gz]` (a bundle with scenes also `<name>.scenes.<hash>.bundle[.gz]`).

### 9. A lambda as a scope root is the compile error `CINGR017` (BREAKING)

### 16. ContainerGenerator: a Release build without the copy into Analyzers

Who: games whose test script builds `ContainerGenerator` in Release (or runs `ContainerGenerator.Verify` in Release) in
the same tree where the Unity tests run at that time.

A Release build copies `ContainerGenerator.dll` into `client/core/Analyzers`. If this happens during a batchmode EditMode run,
Unity requests a compilation of the scripts that cannot finish before the end of the run; while it hangs, `EditorApplication.isCompiling == true`,
the UniTask loop in the editor stands still, and every test that waits for a frame or a timeout ends only by the timeout of the test framework (180 s).
The property `-p:SkipAnalyzersCopy=true` (for `dotnet run` - `--property:SkipAnalyzersCopy=true`) builds without the copy; without it the behaviour
is the previous one.

Search: `grep -rn "ContainerGenerator" tools/scripts/*.sh .github/workflows/*.yml`

Do: where the build runs next to Unity on the same tree, add the property. A script that puts a fresh dll into the
`Analyzers` of a snapshot before Unity on purpose (storytale-workshop `run-tests/generator.sh`) stays as it is.

## Check the behaviour

Content (steps 1-8):

- Play Mode: nothing is built or loaded, a reference gives the asset of the project (`AssetDatabase`), the roots come from the `ContentBundle` asset
  (no asset named `ContentOptions.Name` - `No ContentBundle asset <name>`); a release destroys nothing.
- The end of the lifetime of a load releases the object / unloads the scene; a waiter gets `OperationCanceledException`. A bundle unloads
  with its last load: while another load or a registration holds it, a released reference has `IsLoaded == false`, and the object is alive.
- `Progress(...).Total` is 0 for bundles on the device (standalone, Android, preloaded, Play Mode).
- `LoadNow` / `EnsureLoaded` throw (`... needs a fetch: load it with Load`) for a bundle that is not on the device, except
  the preloaded groups (`AddContent` downloads them); a reference created in code past the build - `... is in no content bundle`.
- Web: the second opening makes no request to `Content/` (Cache API); over http there is no Cache API.
- A scene with `m_LightingDataAsset {fileID: 20201}` (the default lighting data) pulls the built-in cubemap into the bundle: the warning
  of `[ContentBuild]` about built-in resources - clear the field in the scenes without baked light.
- Bundles for a target other than the one selected in Build Settings (standalone tests in a project with WebGL selected) are built: for the time of the build
  the built target is selected, then the previous one comes back.
- Startup trace: `Content: catalog`, `Content: bundle <name>`, `Content: roots <name>`, `Content: bind catalogues`, `Group: <name>`,
  `Content: load <type>`; the loads - `AssetLoads` with the key `Content: <name>`.

Telemetry over HTTP (step 13): a page in the background that stopped sending loses its session after `IdleAfter` (60 s), where a socket would hold it;
a request that failed on the way starts a new link at the client, the session of the old one closes as `lost`. The socket transport did not change.
