## Steps

### 1. Quick search: the queue of the game `Queue` (BREAKING)

Who: the backend of games with the search of the framework (`Game.Hosting.ISessionSearch`, `ISessionRequester`: pixel-swarm, storytale-workshop
(`NoSessionSearch`), neon-dodge - done), the protocol of games whose union contains `SharedSessionRequests.Search` (pixel-swarm, mines-leader,
neon-dodge), and the client of games with the `lobbies` module (`IMatchmaking`: neon-dodge - done; pixel-swarm, mines-leader and peace-data-reborn have their own
`IMatchmaking`). The search carries an integer `queue` from the client to the search of the game: matches of different queues do not mix, what a queue means (a mode,
a map) is decided by the game; 0 by default.
Search: `git grep -nE "ISessionSearch|GetOrCreate\(|ISessionRequester|\.Request\(session|SearchSession" -- backend client/Assets` and
`git grep -n "SharedSessionRequests+Search" -- backend`.
Do:
- `ISessionSearch.GetOrCreate(Guid userId, out bool isLobby)` -> `GetOrCreate(Guid userId, int queue, out bool isLobby)`: the implementation of
  the game (`backend/Game/Global/SessionSearch.cs`, a stub like `NoSessionSearch`), its calls and fakes in tests; a game without queues
  ignores `queue` (0 comes). An own `ISessionSearch` of the game (not `Game.Hosting`) stays untouched.
- `ISessionRequester.Request(Guid userId)` -> `Request(Guid userId, int queue)`: the search command of the meta passes
  `SharedSessionRequests.Search.Queue` (`SearchSessionCommand` / `SessionCommands.SearchSession`), substitutes of `ISessionRequester` in tests
  (`requester.Request(id)` -> `requester.Request(id, 0)` / `Arg.Any<int>()`).
- `IMatchmaking.SearchSession(IReadOnlyLifetime lifetime, int queue = 0)`: direct calls do not change; a method group
  (`_matchmaking.SearchSession` as `Func<IReadOnlyLifetime, ...>`) with an optional parameter does not match - the lambda
  `l => _matchmaking.SearchSession(l)`; own implementations and fakes of the framework `IMatchmaking` (`FakeMatchmaking`) take the new signature.
- A new member `SharedSessionRequests.Search.Queue` (`int`): the protocol golden files of the game (`protocol_schema.golden.txt`,
  `protocol_bytes.golden.txt`, the line `Shared.SharedSessionRequests+Search`) are rewritten with `UPDATE_PROTOCOL_GOLDEN=1`, the protocol hash of
  the game (`ProtocolHash`) is raised: the format of `Search` on the wire is different. Without it `Bytes_MatchGolden`, `Schema_MatchesGolden`,
  `ProtocolHash_MatchesSchema` fail (checked on mines-leader).

### 2. The client MemoryPack without the formatters of rare collections

Who: the client, the protocol types of the game (`[MemoryPackable]` in `shared/` and in the client). On 2026-11-24 no game uses them.
Search: `git grep -lE '\[MemoryPackable' -- '*.cs' ':!*/Tests/*' | xargs grep -nE '\b(HashSet|Queue|Stack|LinkedList|SortedSet|SortedDictionary|SortedList|PriorityQueue|Concurrent\w+|ObservableCollection|ReadOnlyCollection|BlockingCollection|ArraySegment|Memory|ReadOnlyMemory|ReadOnlySequence|IList|ICollection|IEnumerable|IReadOnlyCollection|ISet|IReadOnlySet|IDictionary|ILookup|IGrouping)<|\b(decimal|DateTimeOffset)\b'`
Only serializable members count: a method that returns `IEnumerable<T>` (as `CollectElementIds` in storytale-workshop) does not matter.
Do: replace a type of the list in the protocol with an array, `List`, `Dictionary`, `IReadOnlyList` or `IReadOnlyDictionary`. Otherwise the client
throws `MemoryPackSerializationException` "not registered" on the first serialization (the backend on the full MemoryPack from NuGet will not notice it).
The list of what was removed: `client/packages/com.cysharp.memorypack/FORK.md`.
