# 0.4.0

53 commits (`v0.3.0..HEAD`). The client telemetry is extended: the frame by phases, GPU, WebGL, the page, an unclosed previous session, warnings, loads of assets, the page before Unity in the startup trace; the telemetry protocol changed. The network sends without allocations (API of the socket, the writer and the properties). The screen canvases of the framework are drawn where the game says (`IScreenCanvasCamera`), the latency overlay has its own font. The WebGL build requires the stripping of submodules and puts the sound of iOS into the playback mode. `deploy-client` builds the targets in parallel without the editor, a new skill `device-lab`. `ILobbyMatches.Create` gets the leader of the lobby.

### 2. Telemetry: the page before Unity in the startup trace, loads of assets

Who: games with the telemetry (WebGL templates) and games that load Addressables bypassing the catalogue groups and the scenes of the scopes.

Search: `git grep -nE 'createUnityInstance|loaderUrl|telegram-web-app.js|WebApp.ready|startupTrace' -- 'client/Assets/WebGLTemplates/*/index.html' 'client/Assets/WebGLTemplates/*/TemplateData/*.js'`;
`git grep -nE 'Addressables\.(Load|Instantiate)' -- 'client/Assets/*.cs'`

- The template includes nothing itself: the WebGL build puts `window.startupTrace` as the first script into the `<head>` of the built `index.html`
  (`TelemetryStartupTraceInjection`, the build fails on a page without `<head>`). The template only sets the spans, names without digits:
  - around a blocking SDK of the platform in the `<head>`: `<script>startupTrace.begin('Telegram SDK')</script>` before `telegram-web-app.js`,
    `<script>startupTrace.end('Telegram SDK')</script>` after it;
  - the loading wheel: `startupTrace.begin('Loading wheel')` when shown, `startupTrace.end('Loading wheel')` when hidden;
  - the loader: `startupTrace.begin('Unity loader')` before `document.body.appendChild(script)`, `startupTrace.end('Unity loader')` in `script.onload`;
  - the instance: `startupTrace.begin('Unity instance')` before `createUnityInstance`, in the progress callback once each `startupTrace.mark('Progress quarter')`,
    `'Progress half'`, `'Progress three quarters'`, `'Progress done'`, in `.then` `startupTrace.end('Unity instance')`, in `.catch`
    `startupTrace.mark('Unity instance failed')`;
  - Telegram: `startupTrace.mark('Telegram ready')` next to `Telegram.WebApp.ready()`.
  Example: `client/Assets/WebGLTemplates/Default/index.html` of pixel-swarm. A game without the telemetry does not need to touch the template.
- The loads of the catalogue groups and the scenes of the scopes are marked by themselves (`AssetLoads` of the core). Wrap a load of Addressables that bypasses them:
  `var load = AssetLoads.Begin("Group: <name>");` ... `load.Finish();`, on an exception `load.Fail(exception)`. Found:
  peace-data-reborn `LocationBuilder.cs`, storytale-workshop `NodesRegistry.cs`, `HardcodedBookPlayer.cs` (the editor
  `NodesRegistryGenerator.cs` is not needed). Nothing breaks without the wrapper: the load is just not visible in the telemetry.


### 3. Network: sending without allocations

Who: the client, games with their own implementations of `IWebSocket`, `IConnectionWriter`, `INetworkProperty` (usually fakes in the tests), `BREAKING` (API; the format on the wire is the same).

Search: `git grep -nE 'class \w+[^{]*[:,] *(IWebSocket|IConnectionWriter|INetworkProperty)\b' -- 'client/Assets/*.cs'`

- `IWebSocket.Send(byte[])` became `Send(ArraySegment<byte> bytes)`: the bytes belong to the caller again once the task has completed;
  a socket that holds them longer copies them (`bytes.ToArray()`). A call with `byte[]` compiles as is.
- `IConnectionWriter` got `void WriteOneWay(ReadOnlySpan<byte> message)` (the bytes of an `IMessageFromClient`, copied at once); for a fake
  `=> throw new NotSupportedException()` is enough.
- `INetworkProperty` got `void Collect(IBufferWriter<byte> buffer)`. For an implementation like `NetworkProperty`:
  `public void Collect(IBufferWriter<byte> buffer) { _isDirty = false; MemoryPackSerializer.Serialize(buffer, Value); }`
  (`using System.Buffers;`). peace-data-reborn: `DamageNetworkProperty`.
- A message is serialized at the moment of `WriteOneWay` / `WriteRequest` / `WriteResponse`, not in the send loop: the message object may be
  reused right after the call.
- `ViewableDictionary.Values` is now a struct collection (`foreach` without allocations); through `IReadOnlyDictionary` it is still `IEnumerable`.
  It used to be `IEnumerable<TView>`, the code compiles as is (an assignment to `IEnumerable<T>` boxes).

### 8. The WebGL build requires the stripping of submodules

Who: the client, games with `com.noncasted.framework.platform.web`, `BREAKING`. `Internal.WebGlBuild.Build` loads the settings of the Web
Stripping Tool before the build and throws (exit 1 in batchmode) if there are no active settings or their `SubmodulesToStrip` is empty;
it turns `StripAutomaticallyAfterBuild` on by itself (and saves it into `Settings.json`).

Search: `ls client/ProjectSettings/Packages/com.unity.web.stripping-tool/Settings.json; grep -n 'stripping-tool' client/Packages/manifest.json`

- The web package now depends on `com.unity.web.stripping-tool`: `manifest.json` needs the line of the fork
  `"com.unity.web.stripping-tool": "file:../../tools/framework/client/packages/com.unity.web.stripping-tool"` (without it the package
  from the registry without the patches is pulled in, and `LoadSettings` is not found).
- A game without the settings (storytale-workshop): create a `SubmoduleStrippingSettings` asset (Assets > Create > Web Optimization), fill
  the list of submodules, Assets > Web Optimization > Set as Active Submodule Stripping Settings, commit the asset and
  `ProjectSettings/Packages/com.unity.web.stripping-tool/Settings.json`.

### 11. Hosting: the leader of the lobby in `ILobbyMatches.Create`

Who: the backend of games with lobbies (an own implementation of `ILobbyMatches`, fakes in the tests), `BREAKING`.

Search: `git grep -nE 'LobbyMatch Create\(' -- '*.cs'`

- The signature `Create(Guid lobbySessionId, Guid leaderId, IReadOnlyList<Guid> userIds, bool isOpen)`: `leaderId` is the meta id of the leader
  of the lobby at the moment of the start (the owner of the lobby session, one of `userIds`). A game whose match is hosted by a client (P2P) should give the role
  of the owner of the match to it, not to the first one who entered: otherwise the host is whoever loaded faster. Example: `backend/Game/Global/LobbyMatches.cs`
  of pixel-swarm. peace-data-reborn also has its own interface `backend/Game/Session/Services/LobbyMatches.cs` with the same signature.

## Check the behaviour

- `LifetimedValue`: the lifetime of a value is created on the first access, `Notify` without listeners allocates nothing; after `Dispose`
  `ValueLifetime` stays terminated. Check code that compared `ValueLifetime` by reference before and after `Notify`.
- `SafeAreaPadding` is recalculated only when the safe area or the size of the root changes, not every frame.
- `NetworkProperty.Set` compares through `EqualityComparer<T>.Default`: for a value type with its own `Equals(T)` without `Equals(object)`
