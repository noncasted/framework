# 0.7.0

72 commits (`v0.6.0..27cfedac`, 10 of them merges). The main part: the fixes of the backend audit of 2026-11-14 (the contract of a connection, the reservation of
a seat with a reason, the states of the cluster through methods and the exit of a replaced coordinator from the deploy, meters and traces in the features themselves,
`AddConsoleInfrastructure`, dead code removed) - almost all BREAKING for the backend. Also: a new optional module `match-metrics`
(client, intake and read backend), a reconnect window for the session of a host client, Regenerate All refuses a second bindings file and
ends with the validator.

The tags `v0.7.0-rc.*` in the local clone of the framework are the frozen line `content-directories`, they are not in origin and this release does not include it.

## Steps

Every search from the root of the game. No matches: the step is skipped. Steps 1-2 are the client, 3-4 optional modules, 5-11 the backend of every game.

### 1. Bindings: the class is already generated in another folder (BREAKING)

Who: the client, games with prefabs or scenes whose `*Bindings.g.cs` do not lie in `Generated` of the assembly the generator now
assigns them to (a prefab moved to a folder of another assembly, a bindings file moved by hand).

Before, the generator silently wrote a second file of the same class (CS0101 / two classes with one name), now it refuses with the error
`... is already generated into <file>, and this object resolves to <new path>`, and Regenerate All fails with
`N bindings failed to regenerate`.

Check: `Tools/Framework/Codegen/Regenerate All` (`-executeMethod Internal.RegenerateAll.Run`), then
`grep -n "is already generated into" client/Logs/*.log` (or the editor log). For every line: move the asset back under the assembly of the file
(`git mv` together with `.meta`) or move the file `*.g.cs` with its `.meta` to the path from the error.

Along the way Regenerate All binds again the bindings with an empty reference (`{fileID: 0}`) whose code did not change: the log has
the warning `holds N empty references: binding again`, the prefab is saved again. No action needed, commit the changed prefabs.

### 2. Bindings: Regenerate All ends with the validator (BREAKING)

Who: the client, every game with bindings.

After the binding pass Regenerate All runs `HierarchyBindingsValidator` over every prefab with bindings and the loaded scenes.
Before, the validator was called only from `RegeneratePrefabs` and from the menu, so old findings (a variant removed a component of the base, an empty
reference, an outdated structure, bindings not in the list of the view) now show up as errors in the console; the last line
`Regenerate All: N prefabs and M scenes validated in T ms, E validation errors` is an error when `E > 0`.

Check: Regenerate All, in batchmode or without the focus of the editor then `HierarchyBindingsGenerator.PumpPending()` until `Idle.`;
`grep -n "HierarchyBindingsValidator\|validation errors" <editor log>`. Fix every finding as its text says
(Regenerate in the asset, Scan on the view, return the component in the variant). Scripts of the game that wait for the end of Regenerate All by
`HierarchyBindingsGenerator.HasPending()` take into account that it stays `true` until this check
(`git grep -nE 'HasPending\(|RegenerateAll' -- '*.cs' '*.sh' '*.py'`).

### 3. A reconnect window for the session of a host client (optional)

Who: games with P2P matches (`LocalSessionServer` as the host of a match). Without action the behaviour is the same as before.

Search: `git grep -nE 'LocalSessionServer\.Create|new SessionCore\(' -- 'client/Assets/*.cs'`

- `LocalSessionServer.Create(id, type, maxUsers, services, reconnectWindow)`: with a non-zero window a lost connection of a guest without
  `Leave` does not end their seat: the others get `RemoteAway`, a guest with a ticket of the same user returns to the seat with
  their entities (`LocalUpdate.IsReturn`, `SeatEntities`), when the window expires the seat ends (`RemoteDisconnect`).
- `SessionCore(..., isReconnectable)`, `SeatAway`, `ExpireAway`: the same for an own host without `LocalSessionServer`.

### 4. Module match-metrics: the game data of a match (optional)

Who: games that want to write the series and events of a match; pixel-swarm already plugged it in before the release. A game without the module: nothing (the tags
in its union are not required). Doc: `.claude/docs/MATCH_METRICS.md`, contract: `backend/MatchMetrics/Contract/CONTRACT.md`.

Client. The module `client/modules/match-metrics` (assembly `Internal.MatchMetrics`, namespace `Global.MatchMetrics`): a stream per run
`IMatchMetrics.Open(lifetime, matchId, IMatchMetricsClock)`, series `Counter` / `Gauge` with tags (`MatchTags`, up to 4), events
`Event(name, MatchEventField...)`, buckets of 1 s of the clock of the run, batches once every 30 s over the meta socket, one in flight, a retry after
a reconnect. Protocol: `shared/MatchMetrics/SharedMatchMetrics.cs`, tags `NetworkContextTags.MatchMetrics*` 220-223 (range 220-229).
- `client/Packages/manifest.json`: `"com.noncasted.framework.match-metrics": "file:../../tools/framework/client/modules/match-metrics"`.
- In the union of the game (`git grep -n "TelemetryStartupTraceResult" -- shared/Protocol/NetworkContextUnion.cs`): four lines
  `SharedMatchMetrics.Open/Opened/Batch/BatchResult`, then update the golden files and the protocol hash.
- The meta backend of the client is registered as `IMatchMetricsSocket`, `AddSocketMatchMetrics()` in its scope; the offline meta answers
  `Open` with `Opened { Ok }`, `Batch` with `BatchResult { Ok }`.

Intake backend. The project `backend/MatchMetrics` (assembly `Framework.MatchMetrics`, namespace `Game.MatchMetrics`): the streams of the clients over
the meta socket (`IMatchMetricsConnections.Of(session.Lifetime, session.UserId)`: `Open`, `Accept`), a parser with limits, the server stream
(`IMatchMetricsWriter.Open(lifetime, matchId)`), the storage: 6 own Postgres tables through `IDbSource` (`MatchMetricsSchema`), not
grain states. Who may write into a match is the answer of the game (`IMatchMetricsAdmission`).
- The csproj of the meta gateway, the deploy setup and the tests: a `ProjectReference` to `tools/framework/backend/MatchMetrics/MatchMetrics.csproj`,
  the project in the `.slnx` of the game.
- Meta gateway: `builder.AddMatchMetrics()` (or an own `AddMatchMetricsCommands` with the commands `SharedMatchMetrics.Open` / `Batch`
  over `IMatchMetricsConnections`, the id of the user from the session of the socket) and `builder.AddMatchMetricsAdmission<T>()`: an own
  implementation of `IMatchMetricsAdmission.Check(matchId, userId)` (`MatchMetricsAdmit(IsPlayer, ClosedAt)`); without it the host does not build
  the commands.
- Deploy setup: `await MatchMetricsSchema.Create(connection)` (next to `AuditLogTable.Create`, step 10).
- A host that writes the server stream (the game server): `builder.AddMatchMetricsWriter()`.

Reading. `IMatchMetricsReader` (`backend/MatchMetrics/Reading`): the streams of a match, the dictionary of the series, points by tag groups (step 1 / 10 / 60 s,
the axis of the clock of the run or the server one), the totals of a match and across matches, events. In the host with reading (the meta gateway) `builder.AddMatchMetricsReader()`
and `app.MapMatchMetricsRead().RequireConsoleToken()` (the token is the game's own, as for `MapClientTelemetryRead`).

A game that plugged the module in before the release (pixel-swarm):
- `git grep -nE 'MatchMetricsLimits\.|MatchMetricNames\.' -- '*.cs'` - `Shared.SharedMatchMetricsLimits` / `Shared.SharedMatchMetricNames`
  (`IsName`, `IsKey`, `IsValue`); the client `MatchMetricsLimits`, `MatchMetricNames.IsValid` and the server
  `Game.MatchMetrics.MatchMetricNames` are removed. The storage types and the parser of the backend became `internal`.
- `git grep -n "IMatchMetricsServerStream" -- backend` - `Event` / `Gauge` throw after the end of the lifetime of the stream: do not write after the end of
  the session.
- The parser rejects (`Rejected`) overlapping chunks of one slot and a series declared in two slots; `Duplicate` returns the stored
  slots, a bucket twice in one batch is `Rejected`.

### 5. Backend: the owner of a connection waits for its close, the server sends no requests to the client (BREAKING)

Who: the backend of every game (meta and game gateways, own implementations of connections and copies of the network tests).

`Connection.Run` without a subscriber of `Reader` closes the socket and throws an exception. `IConnection.Closed` is the task "the socket is closed", after
it the owner leaves the handler (otherwise Kestrel tears down the socket together with the close frame, the client sees 1006). There are no more server requests to the client:
`WriteRequest`, `Responses`, `OnRequestHandled`, `PendingRequestsCount`, `ConnectionWriterOptions.RequestTimeout` are removed.
A message of the client that is not accepted (not readable, null, a response of the client) closes the connection (`InvalidPayloadData` / `ProtocolError`).
The handshake is limited to 16 KiB.

- Meta gateway: `git grep -n "connection.Run().NoAwait()" -- backend/Orchestration`. First subscribe the dispatcher
  (`_entryPoint.OnConnected` / `UserCommandsDispatcher.Run`), then `var run = connection.Run();`; after the end of the session
  `lifetime.Terminate()` and `await connection.Closed`, only then leave the middleware.
- Game gateway: `git grep -n "user.Lifetime.Listen" -- 'backend/*SessionGate.cs'` - in `Join` after the end of the lifetime of the user
  `await ((IHostedUser)user).Socket.Closed`.
- Dispatcher: `git grep -nE "reader.Responses|OnRequestHandled" -- backend` - remove the subscription to `Responses` and `HandleResponse`.
- Own `IConnection` / `IConnectionReader` / `IConnectionWriter` (the test worlds of pixel-swarm `SessionTestWorld`, storytale
  `ConstructorTestWorld`, the mocks in `UserConnectionEntryPointTests`): `git grep -nE "IConnectionWriter\b|: IConnection\b" -- backend` -
  add `Task Closed`, remove `Responses`, `WriteRequest`, `OnRequestHandled`.
- Copies of the network tests (mines-leader, peace-data-reborn, pixel-swarm): `git grep -nE "WriteRequest|PendingRequestsCount|RequestTimeout|Responses" -- backend/Tools/Tests`
  - remove the tests of server requests; an unreadable payload now closes the connection.

## Check the behaviour

- Meta and game gateways: a normal exit of a client closes with the code 1000, not 1006; no `Connection is terminated` in the log on a disconnect.
  A message the server cannot read now closes the connection instead of being lost.
- A lobby held only by a stale connection of the player themselves answers `NotFound` (before: `Full`); a late player with such a lobby gets
  a new one.
- A coordinator replaced by a new deploy stops its `DeployLifetime`: `OnlineTracker`, the channel listeners. The list of open lobbies
  no longer shows the lobbies of servers that are not in discovery.
- `DurableQueue`: a retry waits for the observer whose delivery failed; if it did not come back, a dead letter after `MaxRetryCount`.
  `AddressableState.SetValue` repeats the publish of the stored value. `IsOrleansStarted` becomes `true` at the stage `Active`.
  `StateStorageReader.ReadPage` throws instead of an empty or short page. `SideEffectsWorker` keeps the reason of a transaction failure.
- `NoAwait` reports an error that only wraps a cancellation. The connection to the database is retried only on transient failures.
- Console: Requeue Stuck takes only the records older than `StuckThresholdMinutes`; the side effects monitor shows the last aggregate at once,
  a silent service as failed; the live telemetry pages read again after a failure; the audit log reports the errors of its database;
  the online statistics in the time zone of the browser.
- Client telemetry: a failed clean close stays ended.
- Regenerate All: steps 1-2.
