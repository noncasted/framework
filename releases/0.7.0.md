# 0.7.0 (release candidate rc.4)

Кандидат `v0.7.0-rc.2`, ветка `content-directories`: `v0.7.0-rc.1` (15 коммитов `v0.6.0..6837150` и релизный, один из них — `device-lab`
из `main`), сжатие каталога brotli в вебе с исправлением `verify.sh` (шаг 8, rc.2), очередь загрузок и типы каталога в
плеере (шаг 9, `v0.7.0-rc.3`), архив каталога с Range-загрузками и индекс вне `.data` (шаг 10, `v0.7.0-rc.4`). Контент после старта
(группы каталогов, сцены скоупов, ленивые ссылки) — один content directory Unity 7000 вместо Addressables: собирается с каждой сборкой
плеера, грузится через `IContentLoader` на lifetime владельца, в вебе докачивает диапазоны архива по требованию и держит их в Cache API. Форк
Addressables и всё, что на нём держалось, удалены (BREAKING). Модель и API: `.claude/docs/CONTENT.md`. Финальный `0.7.0` — после
перевода pixel-swarm (шаги задачи `content_directories` [10]–[17]).

### 1. Секция `Content` в `Framework.json`, сборка плеера собирает каталог (BREAKING)

Кому: клиент всех игр. Любая сборка плеера (`Internal.WebGlBuild.Build`, `deploy-client`, окно сборки, `-build*Player`) собирает
content directory из секции `Content` файла `ProjectSettings/Framework.json` (`ContentBuild`): без секции сборка падает. `WebGlBuild`
больше не вызывает `SharedAddressablesSync.Sync()`.

Поиск: `grep -n '"Content"' client/ProjectSettings/Framework.json`

- Добавить `"Content": { "Name": "<имя>", "Roots": [ "Assets/<ContentFolder>/Runtime/Catalogues/ContentRoot.asset" ], "IsPreloaded": false }`
  (`IsPreloaded: true` — весь каталог в `.data` WebGL: без запросов, но больше первая загрузка).
- Пустой `Loadable` / `LoadableSceneId`, ссылка на ассет вне каталога, ключи ссылки не от её id — ошибка сборки со списком.
- На время сборки создаются `Assets/FrameworkContentIndex` (индекс в `Resources`) и
  `Library/PlayerDataCache/WebGLPreloadedStreamingAssets/framework-content.manifest`; после сборки удаляются. `Assets/FrameworkContentIndex`
  добавить в `.gitignore` игры (останется, только если редактор упал посреди сборки).
- Лог сборки `[ContentBuild]`: файлы, raw / brotli, файлы без загрузки, встроенные ресурсы в каталоге. `unity_builtin_extra` в каталоге
  (~0.5 MB) — сцена с `m_LightingDataAsset {20201, unity_builtin_extra}`: очистить поле у сцен без запечённого света.

платформы, в Play Mode — ассеты проекта по `Content.Roots`; имя в `ContentOptions` должно совпадать с `Content.Name`). Затем в скоупах

`await builder.LoadContent(reference)` и `builder.RequestContent(reference, out var slot)` (`slot.Value` после сборки), во время игры —
`[Inject] IContentLoader` (`Load`, `LoadScene`, `Fetch`, `Progress`, `LoadNow`) на lifetime владельца. `IScopeBuilder` получил
`ScopeContent Content`, конструктор `ServiceScopeSceneLoader` — `(lifetime, content)`.

Поиск: `grep -rn ": IScopeBuilder\|new ServiceScopeSceneLoader\|WithAssetScene\|FindOrLoadScene" client/Assets --include='*.cs'`

- Корневой `Construct` — `await builder.AddContent(options)`; `ContentOptions` — поле опций игры (`_name`, `_remoteUrl` для CDN, пусто —
  `StreamingAssets` страницы).
- Свои реализации `IScopeBuilder` (тесты) — добавить `public ScopeContent Content => ...`.

### 3. Каталоги на content directory: `ContentRoot`, `IsPreloaded`, `Scenes.X` — `ContentScene` (BREAKING)

Кому: клиент всех игр. Группы каталогов (env assets, prefabs, audio, sprites) грузятся через `IContentLoader` по ссылкам
сгенерированного `ContentRoot` (`<ContentFolder>/Runtime/Catalogues/ContentRoot.asset`: группы, предзагруженные группы, сцены папок
сцен вне Build Settings). `AddContent` привязывает к нему каталоги (`CatalogContent`) и скачивает файлы предзагруженных групп. API групп
прежний (`Retain` / `Release`, `RequestAssetGroup`, `LoadAssetGroup`, `EnsureLoaded`). Удалены `StaticScene` и перегрузки сцен скоупов с
`AssetReference`: `ServiceScopeSceneLoader.Load(AssetReference)`, `AssetScene`, `WithAssetScene(AssetReference)`,
`LoadTyped` / `FindOrLoadScene` / `FindOrLoadSceneWithServices(AssetReference)`, `LoadedScene`.

Поиск: `grep -rnE "IsAddressable|SetAddressable|Scenes\.[A-Za-z0-9]+\.Value|StaticScene|\.Address\b|ResourcePath" client/Assets --include='*.cs'; grep -rln nonAddressable client/Assets`

- `Content.Roots` (шаг 1) — путь `ContentRoot`, затем Regenerate All (шаг «Content root» вместо «Shared addressables»; генератор ещё и
  перед каждой сборкой каталога). Корень руками не править.
- `IsAddressable` → `IsPreloaded` (обратный смысл: `true` у бывших групп из `Resources`); в json-списках групп ключ `nonAddressable`
  переименовать в `preloaded` (старый ключ — исключение генератора). Ассеты групп из `.../Resources/AssetGroups`, `.../Resources/PrefabGroups`
  Regenerate All удаляет и пишет заново в папку каталога; пустые папки `Resources` удалить.
- Сгенерированные классы групп: `AssetGuid` вместо `Address` / `ResourcePath`; свои определения групп (`ICatalogGroupDefinition`) —
  `Guid` / `SetGuid` вместо `Address` / `SetAddress`. `AssetGroup<TAsset>` требует `TAsset : ScriptableObject`.

### 7. `deploy-client`: проверка content directory, нужен `brotli`

Кому: игры с `deploy-client`. `verify.sh` вместо `StreamingAssets/aa/catalog.bin` и дублей бандлов проверяет content directory:
`Library/Content/<Content.Name>` копии свежий, индекс с хэшем его манифеста есть в `.data`, без `IsPreloaded` в
`StreamingAssets/Content/<Content.Name>` ровно `<file>.br` его файлов (манифест среди них), каждый распаковывается в файл

Поиск: `command -v brotli`

### 8. Каталог в вебе едет сжатым brotli (rc.2)

Кому: клиент игр с WebGL и Brotli (`webGLCompressionFormat: 0`) без предзагрузки каталога.

Поиск: `grep -nE "webGLCompressionFormat|webGLDecompressionFallback" client/ProjectSettings/ProjectSettings.asset "client/Assets/Settings/Build Profiles/"*.asset; grep -nE "location|Content-Encoding|try_files" client/deploy/nginx.conf`

- Сборка пишет `StreamingAssets/Content/<name>/<file>.br` (без `BuildManifestHash.txt`), плеер качает `<file>.br`. Сервер обязан отдавать их
  с `Content-Encoding: br`, как `Build/*.br`: общее правило nginx `location ~* \.br$` это уже делает. Если у `StreamingAssets/` есть свой
  `location` (pixel-swarm `client/deploy/nginx.conf`), в нём повторить правило `\.br$` с `Content-Encoding: br`; там же
  `Cache-Control: "public, max-age=31536000, immutable"` (имена — хэши) и `try_files $uri =404` (иначе отсутствующий файл приходит как
  `index.html` 200 и падает по размеру). Для вложенной сборки (`/tg/`) то же внутри её `^~`-блока.
- Brotli с `Decompression Fallback` теперь роняет сборку (`... does not work with the decompression fallback`): выключить fallback (сервер
  шлёт `Content-Encoding`) или `IsPreloaded`.
- LAN-сборки по http (`WebGLCompressionFormat.Disabled`, P3 `WEBGL_TROUBLESHOOTING.md`) и Gzip качают сырые файлы, как раньше.
- После обновления в Cache API игроков старые URL без `.br` удаляются сами при старте (`KeepOnly`).

### 9. Очередь загрузок веба, типы каталога в плеере (rc.3)

Кому: клиент всех игр; код — только тем, кто вызывает `ContentLoader.Register` сам (обычно никто: его зовёт `AddContent`).

Поиск: `grep -rn "ContentLoader.Register" client/Assets --include=*.cs`

- `ContentLoader.Register(lifetime, name, remoteUrl)` → `Register(lifetime, ContentOptions)` (BREAKING); для кода есть конструктор
  `new ContentOptions(name, remoteUrl, maxFetches)`.
- Новое поле `ContentOptions._maxFetches` (по умолчанию 64): сколько файлов каталога WebGL-плеер качает одновременно, остальные ждут в
  порядке запроса. Сцены и ассеты, сохранённые до него, получают 64 без правки; менять — только если сервер не держит HTTP/2.
- Сборка плеера получает каталог типов сборки контента (`AddPreviousBuildReportDirectory`): типы, нужные только каталогу (коллайдеры
  уровней, компоненты префабов), больше не вырезаются. Действий нет; проверка — в логе плеера нет `contained objects with undefined types`.

### 10. Архив каталога, Range-загрузки, индекс отдельным файлом (rc.4, BREAKING)

Кому: клиент игр с WebGL (сервер статики и его конфиг); код — только тем, кто читает `ContentIndex` / `ContentFile` сам или собирает
свой `ContentOptions` в коде (обычно никто).

Поиск: `grep -nE "location|Content-Encoding|Accept-Ranges|gzip|\.br" client/deploy/nginx.conf; grep -rnE "ContentIndex|ContentFile\b|IsBrotli|ShippedSuffix" client/Assets --include=*.cs`

- Каталог едет одним архивом движка (UnityFS, блоки LZ4) в порядке первого использования и индексом рядом:
  `StreamingAssets/Content/<name>/<hash>.archive` и `<hash>.index.json.br` (raw `.json` без brotli); в Resources плеера — только
  `ContentStamp` (хэш), индекс качается один раз при старте. Пофайловых `<file>.br` больше нет. Каталог собирается без type tree
  (`DisableWriteTypeTree`): около 2/3 байтов меньше.
- Сервер (nginx): для `\.archive$` под `StreamingAssets/` (и в `^~`-блоке вложенной сборки `/tg/`) — `Cache-Control: "public,
  max-age=31536000, immutable"`, `try_files $uri =404`, **без** `Content-Encoding` и без `gzip` (Range отвечает `206` с байтами как есть;
  статику nginx отдаёт с `Accept-Ranges: bytes` сам). Индекс `.br` — по общему правилу `\.br$` с `Content-Encoding: br`. Иначе загрузка
  падает с причиной в консоли (`HTTP 200 instead of 206 ...`, `Content-Encoding ...`, `... is no json`).
- `ContentFile(name, size)` → `ContentFile(name, offset, size)`; у `ContentIndex` нет `IsBrotli` / `IsPreloaded` / `ShippedSuffix`
  (они в `ContentStamp`), есть `ArchiveLength`, `Header`. Новое поле `ContentOptions._rangeGap` (16 KiB по умолчанию): файлы не дальше
  этого идут одним запросом; сохранённые ассеты получают его без правки.
- Стенд и dev-серверы игры, отдающие `StreamingAssets/`, должны понимать `Range` (206).
- После обновления старые записи Cache API игроков (пофайловые URL) удаляются при старте (`KeepOnly`).
- rc.5: Range-запросы идут мимо HTTP-кэша браузера (`cache: 'no-store'`) — Chromium пускал запросы одного URL через запись кэша по
  одному, и диапазоны архива шли на сервер последовательно (стенд, 150 мс: меню 24 с против 10 с). Действий нет; свой fetch диапазонов
  (если есть) — тоже с `no-store`.

## Проверить поведение

- Play Mode: каталог не собирается и не регистрируется, `Loadable` отдаёт ассеты проекта (`AssetDatabase`); `Release` их не уничтожает.
  Ошибки пустых ссылок видны только в сборке каталога (или при загрузке пустой ссылки — исключение).
- Лог `[ContentBuild] <name>: ..., R bytes raw, archive A bytes (header H), B bytes shipped in <folder>` — архив и индекс, которые качает игрок.
- Веб: загрузка уровня — десятки Range-запросов к `<hash>.archive` (`206`), не больше `MaxFetches` в полёте; в консоли нет
  `Archive file was modified while it was opened`.
- Веб: первое открытие качает индекс и диапазоны архива по мере загрузок (`load.*` телеметрии с `Content: <name>`), второе — ни одного запроса к
  `Content/` (Cache API). По http Cache API нет: каждый раз заново (лог одной строкой).
- Конец lifetime загрузки освобождает объект / выгружает сцену; ожидающий получает `OperationCanceledException`.
- `LoadNow` / `EnsureLoaded` бросают для объекта, чьи файлы ещё не скачаны (кроме предзагруженных групп — их качает `AddContent`).
- Каталог живёт столько, сколько корневой скоуп: его конец уничтожает всё загруженное из каталога.
