# 0.12.0

`NetworkLatencyOverlay` moved to its own assembly `Internal.Network.Overlay` and is created only if the game plugged it in
(`AddNetworkLatencyOverlay`). A game without uGUI / TMP (a WebGL build without them) can now plug in the `network` module; a game with the overlay
does step 1.

## Steps

### 1. Network: the ping overlay in a separate assembly `Internal.Network.Overlay` (BREAKING)

Who: the client of games with sessions (`AddSessionServices`): pixel-swarm, mines-leader, peace-data-reborn. `Internal.Network` no longer
references TMP / uGUI: the debug overlay `NetworkLatencyOverlay` (N, a three-finger tap) moved to the assembly `Internal.Network.Overlay`
(`client/modules/network/Overlay`, compiled only with the package `com.unity.ugui` 2.x, `FRAMEWORK_TMP`) and is created only if the game
plugged it in. The font left `NetworkOptions` (`LatencyOverlayFont` deleted) for a new asset `NetworkOverlayOptions`.
Search: `git grep -nE "AddSessionServices\(|LatencyOverlayFont|new NetworkLatencyMonitor\(" -- client/Assets` and
`git grep -n "_latencyOverlayFont" -- client/Assets` (the `NetworkOptions` asset).
Do:
- Create a `NetworkOverlayOptions` asset next to the `NetworkOptions` asset of the game (reachable by the session scope in the same way) and set its `Font` to
  the `TMP_FontAsset` that was in `Latency Overlay Font` of the `NetworkOptions` asset.
- The order, if the asset is taken from a catalogue of the game (as `NetworkOptions` from `InternalAssets`): first the asset with the catalogue group in its `.meta`
  (as `NetworkOptions` has), a reference of the asmdef of the content assembly (`Internal.Content`) to `Internal.Network.Overlay` (the generated catalogue
  class names the type `NetworkOverlayOptions`, without the reference CS0246), the generation (`Tools/Framework/Codegen/Assets Catalog`), and only then
  the call below. A call written before the generation breaks the compilation (CS0117 `InternalAssets` without `NetworkOverlayOptions`), and the generator does not
  run without a compilation: after a change of the framework the editor does not bring up the bridge. Found on mines-leader (2026-11-25).
- In the session scope, next to `AddSessionServices()`: `builder.AddNetworkLatencyOverlay(overlayOptions)`; the asmdef of this scope references
  `Internal.Network.Overlay` (`GUID:99f35bbb8b15421ba39cd5252789051f`). Without the call there is no overlay, without the font the constructor of
  `NetworkLatencyOverlaySetup` throws when the scope is built. A game that does not need the overlay has nothing to call.
- Code that creates `NetworkLatencyMonitor` itself (tests): the constructor without `NetworkOptions` and `IScreenCanvasCamera` is
  `new NetworkLatencyMonitor(connection, session, peerMatch, clock)`; the overlay no longer appears there, its life is
  `INetworkLatencyMonitor.IsMeasuring` (`IViewableProperty<bool>`: true from the first round of probes to the end of the lifetime). An own substitute of
  `INetworkLatencyMonitor` implements `IsMeasuring`.
- Unity no longer reads the field `_latencyOverlayFont` of the `NetworkOptions` asset: remove it when the asset is saved again.

## Check the behaviour

- The overlay (N, a three-finger tap) exists only in the session of a scope where `AddNetworkLatencyOverlay` is called: in a game with two session scopes
  (lobby and match), in each one where it is plugged in. It appears after the first round of probes and is destroyed with the end of the session, as before. The log
  of the monitor `[Network] [Latency]` every 5 s, with and without the overlay.
