## Steps

Every search is run from the root of the game. No matches: the step is skipped.

### 1. Profiler: stages of the trace

Who: every game, `BREAKING`. `GameProfiler.Branch` is renamed to `GameProfiler.Stage`. A record made with an empty stack and `Detached` now
go to the last open stage, not to the root of the trace, a parent covers its late children, `LoadRoot` opens the stage `Startup`.
Until the step is done, `Scope("Global")` and the like are nested in `Startup`.

Search: `git grep -nE 'GameProfiler\.(Branch|Detached)\(|GameProfiler\.Scope\("(Global|Meta|Game loop|Menu|Load)' -- 'client/Assets/*.cs'`

- A big step of the game (`Global`, `Meta`, `Game loop`, a menu, a lobby, the load of a match) opened as `Scope` or `Branch` is replaced with
  `GameProfiler.Stage(...)`. A load of a menu or a lobby without its own span gets a stage.
- A parallel branch of a stage is opened with `Detached` in the synchronous part (`OnBaseSetup`): after an `await` the current stage is already another one. Its
  steps hang on this span (`span.Child`), and the requests are created inside `GameProfiler.Ambient(span)`. Example: `MetaLoop` in pixel-swarm.


### 2. Network client: `IConnectionWriter.CurrentRun`

Who: a game with its own implementation of `IConnectionWriter`, `BREAKING`. The property `CurrentRun` is added: the number of the run of the connection. The implementations of `network` already give it, only the fakes in the tests of the game break.

Search: `git grep -nE ':.*\bIConnectionWriter\b' -- 'client/**/*.cs'`

- Add the property to the implementations found.


### 3. Client telemetry (optional)

Who: a game that needs the metrics and errors of its clients. A new module `telemetry`, the projects `backend/ClientTelemetry` and the skill `client-telemetry`. A game without it does nothing. Example: commit `8cc3cdd6` in pixel-swarm.

Search: `git grep -n 'AddSocketClientTelemetry\|AddClientTelemetry' -- '*.cs'`

- Union: the tags `NetworkContextTags.Telemetry*` (200-206). Update the protocol hash and the golden files of the protocol, if there are any.
- Backend: silo `AddClientTelemetrySessions()`, console `AddClientTelemetryReader()` (the panel appears from it). Gateway of the meta socket: `AddClientTelemetry()`, `MapClientTelemetryRead().RequireConsoleToken()` and four commands of the socket over `IClientTelemetryConnections.Of(session.Lifetime)`: `Start`, `Accept`, `End`, `AcceptStartup`.
- Client: `AddSocketClientTelemetry(options)` and `AddStandardTelemetryCollectors()` in the meta scope, `ITelemetrySocket` on the connection to the meta. After every authorization of the socket `SendStartupTrace()`, then `StartSession(lifetime, tags)` for every part of the game, the game chooses the tags; `Mark(name)` if wanted.
- Projects: `ProjectReference` to `backend/ClientTelemetry` in the gateway, silo, console, `GameComposition` (without it `StatesLookup` does not create the tables `state_client_telemetry_*`) and the backend tests if they use it; the project in `.slnx`; the list of states in the test of the `StatesLookup` generator, if there is one. `"com.noncasted.framework.telemetry"` in `manifest.json`, `GUID:f633eeac40e2491984f08e394079da0a` (`Internal.Telemetry`) in every asmdef that calls the telemetry.
- `enableFrameTimingStats: 1` in `ProjectSettings.asset` and in every Build Profile: otherwise there is no `frame.cpu*`, `frame.gpu`.
- Skill: the link `.claude/skills/client-telemetry`, the section `## client-telemetry` (`url`, `env-file`) in `.claude/project-skills.md`.
- Turn the flag on on the Features page of the console: without it the telemetry is not written.
