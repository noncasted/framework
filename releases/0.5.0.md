# 0.5.0

29 коммитов (`v0.4.0..HEAD`). Новые модули `resolution` и `framerate` (разрешение рендера на телефонах, частота кадров 60/30)
и тестовая сборка `Internal.TestTools` переехали из pixel-swarm. Пакеты бэкенда на последних стабильных версиях (Orleans 10.4.2,
Aspire 13.6.4). Из контейнера удалено внедрение в целый `GameObject`. В сети: WebRTC с несколькими каналами и `PeerMesh` (полная сетка
прямых соединений с туннелем). Каталог спрайтов читает и `Assets` модулей игры. Новый скилл `audit-swarm` для oh-my-pi.

## Шаги

Поиск везде из корня игры. Нет совпадений: шаг пропускается.

### 1. Тестовые инструменты: `FrameAllocations`, `WebGlShaderCheck`

Кому: клиент игр со своими тестами аллокаций кадра или проверкой шейдеров для WebGL (pixel-swarm уже перешёл; остальным по желанию).

Поиск: `git grep -nE 'GetAllocatedBytesForCurrentThread|ImmCB_|TempArray|CompileVariant' -- 'client/Assets/*.cs'`

- Новая сборка `Internal.TestTools` (`client/core/Tests/Tools`, только Editor, `UNITY_INCLUDE_TESTS`). Тестовый asmdef игры ссылается
  на неё (`"Internal.TestTools"`), а в `client/Packages/manifest.json` в `testables` должен быть `com.noncasted.framework.core`: без него
  тестовые сборки пакета не компилируются.
- Замер `before = GC.GetAllocatedBytesForCurrentThread(); ...; Assert` -> `FrameAllocations.AssertNone("что", passes, pass, warmup)`
  (`warmup` по умолчанию 10, не считается). Порог: меньше байта на проход, а не ноль; разовая аллокация рантайма (48 Б) не валит тест.
  Assert внутри прохода не ставить: NUnit выделяет память. Только число: `FrameAllocations.Measure(passes, pass, warmup)`.
- Своя компиляция шейдеров под GLES3x -> `WebGlShaderCheck.AssertSafe(WebGlShaderCheck.Find(new[] { "Assets" }, new[] { "Assets/Plugins/" }))`:
  папки и исключения (сторонние шейдеры) задаёт игра. Проверка ловит ещё и flat varyings (`nointerpolation`, G1 в
  `WEBGL_TROUBLESHOOTING.md`), а не только `ImmCB_` / `TempArray`: шейдер с `nointerpolation` теперь валит тест. Пример: pixel-swarm
  `client/Assets/GamePlay/Tests/WebGlShaderTablesTests.cs`.

### 2. Разрешение рендера на телефонах и частота кадров 60/30: модули `resolution` и `framerate`

Кому: клиент игр с WebGL, где есть свои копии этого из pixel-swarm (`Global.Resolution`, `Global.FrameRate`, `webShell.renderPixelRatio`).
Найдено: peace-data-reborn (`client/Assets/WebGLTemplates/{Default,Telegram}/TemplateData/web-shell.js`, `Default/index.html`).

Поиск: `git grep -nE "renderPixelRatio|followRenderPixelRatio|frameRateRequest|setResolution|class (FrameRateLimit|AutoFrameRate|RenderResolution|FrameRateTelemetryMarks|ResolutionTelemetryCollector)\b" client`

- `client/Packages/manifest.json`: `com.noncasted.framework.resolution` и `com.noncasted.framework.framerate`
  (`file:../../tools/framework/client/modules/<имя>`), оба в `testables`; удалить свои копии классов и `.jslib` (типы и пространства
  имён те же: `Global.Resolution`, `Global.FrameRate`).
- asmdef, где используются типы, и каждый asmdef скоупа под скоупом с `AddFrameRate` / `AddResolution` (иначе `CINGR003`, ссылки не
  транзитивны): `Internal.Resolution`, `Internal.FrameRate`; asmdef скоупа телеметрии: `Internal.Resolution.Telemetry`,
  `Internal.FrameRate.Telemetry`.
- Настройки игры реализуют `IResolutionSetting` / `IFrameRateSetting` (свойства `Resolution` / `FrameRate`) и регистрируются
  `.As<IResolutionSetting>().As<IFrameRateSetting>()`.
- Глобальный скоуп: `AddFrameRate(<AutoFrameRateOptions из ассета опций игры>)` после `AddUpdater`, `AddResolution()`. Опции проверяются
  при сборке скоупа на любой платформе: неверные валят скоуп. Скоуп телеметрии: `AddFrameRateTelemetry()`, `AddResolutionTelemetry()`
  вместо своих `FrameRateTelemetryMarks` / `ResolutionTelemetryCollector`.
- WebGL-шаблон: `webShell.renderPixelRatio(max)` -> `renderResolution.pixelRatio(canvas, max)`, `webShell.followRenderPixelRatio(module, max)`
  -> `renderResolution.follow(module, canvas, max)`; из своего `web-shell.js` убрать разрешение и `?fps=` (`render-resolution.js`
  кладётся в `<head>` собранного `index.html` сам, ключ `webShell.resolution` в localStorage сохранён).

## Проверить поведение

- Каталог спрайтов читает кроме `ArtFolder` ещё `<ModuleRoot>/Assets` каждого модуля из `FrameworkSettings.ModuleRoots`: помеченные
  спрайты оттуда попадают в группы `<Модуль>/<Папка>`. После обновления перегенерировать каталог и посмотреть дифф: новые группы
  значит, что в модулях лежали помеченные спрайты, которых раньше в каталоге не было. Папки модулей как группы не предлагаются.
- `SpriteGroupAsset.Sheets` / `SpriteGroup.Sheets` бросают на группе без записей и на листе без спрайта, а не пропускают его.
- UI: `IUIStateEnterHandler.OnEntered`, который бросает, теперь выходит из состояния (ограничения ввода снимаются), исключение идёт
  вызывающему. Раньше состояние оставалось висеть.
- Скрипты, которые сборка кладёт в `<head>` (`BuiltPageScripts`: `audio-session.js`, `startup-trace.js`, `render-resolution.js`),
  встают после `<meta charset>` шаблона, если он стоит перед первым скриптом.

## Без действий

- Сеть: WebRTC с несколькими каналами (`WebRtcPeerOptions(..., channels)`, `IWebRtcChannels`, `WebRtcPeers.CreateChannels`), старый
  конструктор и `IWebRtcPeer` прежние; `PeerMesh` и `IPeerLink` (полная сетка прямых соединений с туннелем через сервер).
- Сеть: `SessionConnection` сразу падает, если сервер закрыл сокет после билета.
- Генератор контейнера: экземпляры одного типа в ветках одного `if/else` делят слот; выбранная ветка `switch` освобождается после
  зависимых.
- Каталоги: `SpriteGroup.GetSheet` / `Sheets`, `EnvAssetGroup.GetAll<T>`.
- Редактор: `CompactMenuBar` ничего не делает в клоне Multiplayer Play Mode; генерация каталогов на паузе в редакторных тестах
  фреймворка.
- `deploy-client`: `client/Library` последней удачной сборки на цель переиспользуется следующей сборкой того же дерева.
- `test-all.sh` называет исходники, изменённые во время прогона.
- `client/measurements`: размер WebGL-сборки по версиям Unity (только для фреймворка).
- Скилл `visualize`: варианты из генераторов проекта.
- `releases/0.1.0.md`: шаг A7 для `AddTelegramAPI` с `TelegramEditorOptions`.
