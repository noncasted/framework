# 0.5.0

and the test assembly `Internal.TestTools` moved from pixel-swarm. The backend packages are on the latest stable versions (Orleans 10.4.2,

## Steps

Every search is run from the root of the game. No matches: the step is skipped.

### 1. Test tools: `FrameAllocations`, `WebGlShaderCheck`

Who: the client of games with their own tests of frame allocations or a check of the shaders for WebGL (pixel-swarm has already moved; for the others optional).

Search: `git grep -nE 'GetAllocatedBytesForCurrentThread|ImmCB_|TempArray|CompileVariant' -- 'client/Assets/*.cs'`

- A new assembly `Internal.TestTools` (`client/core/Tests/Tools`, Editor only, `UNITY_INCLUDE_TESTS`). The test asmdef of the game references
  it (`"Internal.TestTools"`), and `testables` in `client/Packages/manifest.json` must hold `com.noncasted.framework.core`: without it
  the test assemblies of the package do not compile.
- A measurement `before = GC.GetAllocatedBytesForCurrentThread(); ...; Assert` -> `FrameAllocations.AssertNone("what", passes, pass, warmup)`
  (`warmup` is 10 by default, not counted). The threshold: below a byte a pass, not zero; a one-time allocation of the runtime (48 B) does not fail the test.
  Do not put an Assert inside a pass: NUnit allocates memory. The number only: `FrameAllocations.Measure(passes, pass, warmup)`.
- An own compilation of the shaders for GLES3x -> `WebGlShaderCheck.AssertSafe(WebGlShaderCheck.Find(new[] { "Assets" }, new[] { "Assets/Plugins/" }))`:
  the game sets the folders and the exclusions (third-party shaders). The check also catches flat varyings (`nointerpolation`, G1 in
  `WEBGL_TROUBLESHOOTING.md`), not only `ImmCB_` / `TempArray`: a shader with `nointerpolation` now fails the test. Example: pixel-swarm
  `client/Assets/GamePlay/Tests/WebGlShaderTablesTests.cs`.

### 2. The render resolution on phones and the frame rate 60/30: the modules `resolution` and `framerate`

Who: the client of WebGL games that have their own copies of this from pixel-swarm (`Global.Resolution`, `Global.FrameRate`, `webShell.renderPixelRatio`).
Found: peace-data-reborn (`client/Assets/WebGLTemplates/{Default,Telegram}/TemplateData/web-shell.js`, `Default/index.html`).

Search: `git grep -nE "renderPixelRatio|followRenderPixelRatio|frameRateRequest|setResolution|class (FrameRateLimit|AutoFrameRate|RenderResolution|FrameRateTelemetryMarks|ResolutionTelemetryCollector)\b" client`

- `client/Packages/manifest.json`: `com.noncasted.framework.resolution` and `com.noncasted.framework.framerate`
  (`file:../../tools/framework/client/modules/<name>`), both in `testables`; delete the own copies of the classes and the `.jslib` (the types and
  namespaces are the same: `Global.Resolution`, `Global.FrameRate`).
- The asmdef where the types are used, and every asmdef of a scope below the scope with `AddFrameRate` / `AddResolution` (otherwise `CINGR003`, references are not
  transitive): `Internal.Resolution`, `Internal.FrameRate`; the asmdef of the telemetry scope: `Internal.Resolution.Telemetry`,
  `Internal.FrameRate.Telemetry`.
- The settings of the game implement `IResolutionSetting` / `IFrameRateSetting` (the properties `Resolution` / `FrameRate`) and are registered
  `.As<IResolutionSetting>().As<IFrameRateSetting>()`.
- The global scope: `AddFrameRate(<AutoFrameRateOptions from the options asset of the game>)` after `AddUpdater`, `AddResolution()`. The options are checked
  when the scope is built, on any platform: wrong ones fail the scope. The telemetry scope: `AddFrameRateTelemetry()`, `AddResolutionTelemetry()`
  instead of the own `FrameRateTelemetryMarks` / `ResolutionTelemetryCollector`.
- WebGL template: `webShell.renderPixelRatio(max)` -> `renderResolution.pixelRatio(canvas, max)`, `webShell.followRenderPixelRatio(module, max)`
  -> `renderResolution.follow(module, canvas, max)`; remove the resolution and `?fps=` from the own `web-shell.js` (`render-resolution.js`
  is put into the `<head>` of the built `index.html` by itself, the key `webShell.resolution` in localStorage is kept).

## Check the behaviour

- Besides `ArtFolder`, the sprite catalogue also reads `<ModuleRoot>/Assets` of every module of `FrameworkSettings.ModuleRoots`: the marked
  sprites from there go into the groups `<Module>/<Folder>`. After the update regenerate the catalogue and look at the diff: new groups
  mean the modules held marked sprites that were not in the catalogue before. The folders of the modules are not offered as groups.
- `SpriteGroupAsset.Sheets` / `SpriteGroup.Sheets` throw on a group without entries and on a sheet without a sprite instead of skipping it.
- UI: an `IUIStateEnterHandler.OnEntered` that throws now leaves the state (the input constraints are removed), the exception goes
  to the caller. Before, the state stayed hanging.
- The scripts the build puts into the `<head>` (`BuiltPageScripts`: `audio-session.js`, `startup-trace.js`, `render-resolution.js`)
  go after the `<meta charset>` of the template if it stands before the first script.
