# 0.18.4

4 commits (`v0.18.3..ee194207`):

- content: the link.xml of the content bundles (`Library/ContentBundles.link.xml`, `ContentLinkXml`) now also lists the serialized
  classes of the bundled data, taken from `WriteResult.includedSerializeReferenceFQN` of the bundle build, as
  `<type fullname="..." preserve="nothing" serialized="true" />` under their assembly (the form of Unity's `SerializedTypes.xml`, the
  parse of the SBP `LinkXmlGenerator`: `<assembly>:<type>`, nested `Outer/Inner`, generic `Name`1` as they are). Unity's
  `SerializedTypes.xml` covers only the data of the player, so a class named only by a `[SerializeReference]` of an asset in a bundle
  was stripped by IL2CPP at `managedStrippingLevel` High: in peace-data-reborn the 8 `GamePlay.Enemies.*EnemyBehaviour` and
  `HomingMovement` / `DeceleratingMovement` were missing from the WebGL build (the Addressables of before 0.8.0 wrote them through the
  SBP `GenerateLinkXml`). An FQN that is not `<assembly>:<type>` fails the content build.
- `ContentBundleBuilder.Build` / `ContentBuild.Build` return `ContentBuiltContent` (the bundles and `SerializedTypes`), `ContentLinkXml.Write`
  takes it. No game calls them (`git grep -n -e ContentBundleBuilder.Build -e "ContentBuild.Build(" -e ContentLinkXml HEAD -- client/Assets`:
  no hits).
- `deploy/registry.json`: post-radio and gamejam-autobattler on the monolith, peace-data-reborn without the aspire domain.

## Check the behaviour

- After a player build `Library/ContentBundles.link.xml` is removed with the rest of the content build; to see it, run
  `ContentBuild.Prepare(target)` in the editor, read the file, then `ContentBuild.Cleanup()`.
- The link.xml is bigger (every serialized class of the bundled data, not only the `[SerializeReference]` ones); `preserve="nothing"`
  keeps only what serialization needs, so the wasm grows only by the classes that were wrongly stripped.
