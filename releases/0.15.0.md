# 0.15.0

5 commits (`v0.14.0..17ff8ef6`). The client got its own logger: `ILog<T>` in a constructor or an `[Inject]` method (the container
generator gives it without a registration), templates with `{Name}` and generic arguments (nothing is formatted or
allocated below the level, `Debug` is cut out of release), levels by category in the `OptionsContainer` of the game. The runtime of the framework writes through it.
The client telemetry gets the errors of the logger with the category and the template instead of the text (one group per call site, the arguments do not
leave the client) and the marks `log.<level>`; the backend stores the category and takes it into the fingerprint. BREAKING for the client and the protocol of every game.

## Steps

### 1. `DebugOptions.EnableLogs` removed (BREAKING)

Who: the client; on 2026-11-25 no game reads it.
Search: `git grep -nE 'EnableLogs|_enableLogs' -- 'client/Assets/*.cs'`
Do: remove the uses. Unity drops the field `_enableLogs` in `OptionsContainer.asset` on the next save of the asset.

### 2. Log levels in `OptionsContainer`

Who: the client of every game.
Do: Project Tools -> Options -> Log Options. By default development `Info`, release `Warning`, the telemetry marks off
(`None`). If wanted, rules by the prefix of a namespace or a type (`LogRule`: for example `Global.Network` -> development `Debug`; marks
`Info` for the categories needed on the timeline of a session), save the asset. `OptionsContainer.Register` applies it itself.
The hints of the profiler (`ProfilerTraceStorage`: "Trace saved… downloadProfilerTrace()") are `Info`: in release they need
the rule `Internal.ProfilerTraceStorage` -> release `Info`.

### 3. Telemetry protocol: `SharedClientTelemetry.Error.Category` (BREAKING)

Who: games with protocol tests (golden files).
Search: `git grep -n 'SharedClientTelemetry+Error' -- '*.golden.txt'`
Do: a new last member `Category` (`string`) of `Error`. Rewrite the protocol golden files of the game (`protocol_schema.golden.txt`,
`protocol_bytes.golden.txt`, the lines `Shared.SharedClientTelemetry+Error` and `+Batch`) with `UPDATE_PROTOCOL_GOLDEN=1`, raise the
protocol hash of the game (`ProtocolHash`). An old client is compatible with the backend of the new release (MemoryPack writes the number of members,
a missing category is `null`), but the hash keeps the clients of one build together.

### 4. Every log of the game goes through the logger (required)

Who: the client of every game, all the code outside the tests (runtime and Editor). The step is big (tens and hundreds of files): it is done in this same
update, possibly in separate commits by assembly; the build and the tests come after all of them.
Search: `git grep -lE 'Debug\.Log|UnityEngine\.Debug\.Log' -- 'client/Assets/*.cs' ':!*/Tests/*'`
Do: remove every call of `Debug.Log` / `LogWarning` / `LogError` / `LogException` / `Log*Format` and replace it with the logger by
`tools/framework/.claude/docs/LOGGING.md`; after the step the search finds only the exceptions below.
- Where the log comes from: a type the container creates (a registration in an installer of the game or the framework, a MonoBehaviour with `[Inject]`): a parameter
  `ILog<T>` of the constructor or of an `[Inject]` method (no registration needed), the field `private readonly ILog _log`; a type created with `new`
  (if also by tests, they pass `Logs.Of<X>()`), a struct: `private static readonly ILog _log = Logs.Of<X>()`; a static class:
  `Logs.Of(typeof(X))`.
- Text: `Debug.Log($"[Game] [Run] Joined {code} in {ms:F1} ms")` -> `_log.Info("Joined {Code} in {Ms} ms", code, Math.Round(ms, 1))`:
  no manual prefixes `[...]` (the console writes `[ClassName]`), every interpolation is a placeholder `{PascalCase}` with an argument in order
  (0-4; more: merge them or split the line), no formats `{x:F1}`, no `$"..."` and no concatenation in the template, curly braces of the text are
  `{{` / `}}`.
- Level: `LogWarning` -> `Warning`, `LogError` -> `Error`, `LogException(e)` -> `_log.Exception(e)`; a `LogError` of a text followed by
  a `LogException` of the same error -> one `_log.Error(e, "text", ...)`; `Log` -> `Info` for events of the life cycle (once per scene,
  session, run), `Debug` for the chatty ones (per frame, message, packet, callback).
- Tests of the game with `LogAssert.Expect` on these texts expect the new line `[ClassName] text`.
- Exceptions that stay on `Debug.Log*`: a call with a context object (`Debug.Log(text, gameObject)`, the highlight of the object in
  the console of the editor) and `Debug.Log` inside an own `ILogSink`.
- Compiler: a field of a class named `Logs` hides the static class: `global::Internal.Logs.Of<X>()`; `UAC0036` on
  `static readonly ILog` (the automatic cleanup of statics of Unity): the attribute `[NoAutoStaticsCleanup]` on the field.

Only this way an error of the game reaches the telemetry with the category and the template (one group per call site), and `Debug` is cut out of release.

### 5. Constructors of framework types with a log (BREAKING)

Who: tests and tools of the game that create these types with `new`. The registrations of the container do not change: the generator gives the log.
Search: `git grep -nE 'new (SessionControl|SessionConnection|NetworkSession|NetworkObjectsCollection|EntityDestroyedCommand|NetworkLatencyMonitor|FrameRateLimit|AutoFrameRate|RenderResolution|ClientOutdatedNotice|MatchMetrics|MatchMetricsSocketTransport|TelemetryHttpTransport|TelegramDebugAPI|SteamInvites|SteamPlatformAchievements|SteamPlatformInventory|UnitySessionLog)\(' -- 'client/Assets/*.cs'`
Do: `Logs.Of<X>()` as the last argument (for `UnitySessionLog` any `ILog`, the first and only one). Example:
`new SessionConnection(connection)` -> `new SessionConnection(connection, Logs.Of<SessionConnection>())`; the tests of the framework
(`SessionConnectionTests`, `PeerMeshTests`, `NetworkObjectsCollectionTests`) are the model.

## Check the behaviour

- Lines of the framework in the console: `[ClassName] text` instead of `[Network] [Session] ...`; tests of the game with `LogAssert.Expect` on texts
  of the framework expect the new lines (`[SoundPool] ...`, `[ConnectionWriter] ...`, `[NetworkLatencyMonitor] ...`).
- In a release player `Info` of the framework is not written by default (level `Warning`), `Debug` is not compiled (when needed: `FRAMEWORK_LOG_DEBUG`).
  In player builds the lines below `Warning` go without a stack.
- Errors of the framework in the telemetry: with the category, the message is the template (`Lost the room {Code}`); an exception is the template, `\n`, `Type: text`
  and its own stack. Errors of Unity and third-party code: as before, without a category. The lines of `UnitySessionLog` (`SessionCore`) and libdatachannel
  (`NativeWebRtcLibrary`) come as the template `{Message}` / `{Line}`: one group per category.
- `ReactiveExceptions` are written with the category `Internal.ReactiveExceptions`.

## No action

- Telemetry backend: `category` in the rows of `/sessions/{id}/errors`, in the groups of the digest and `/errors`, next to the level in the console;
  a category that is not in the form of a type name or is longer than 256 is dropped, the error stays. The fingerprint without a category is the same as before.
- The scrubbers of the client and the server keep the placeholder `{Identifier}` (up to 31 characters); the PII corpus is extended.
- The skill `client-telemetry` prints `[Category] template`, knows the marks `log.*`.
- `LOGGING.md`, a line in `INDEX.md`, the section Logging in `CLAUDE.md`.
- `Logs.AddSink(lifetime, ILogSink)` for own receivers of the records.
