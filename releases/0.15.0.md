# 0.15.0

5 коммитов (`v0.14.0..17ff8ef6`). У клиента появился свой логгер: `ILog<T>` в конструкторе или `[Inject]`-методе (генератор
контейнера даёт его без регистрации), шаблоны с `{Name}` и generic-аргументами (ниже уровня ничего не форматируется и не
аллоцируется, `Debug` вырезан из release), уровни по категориям в `OptionsContainer` игры. Runtime фреймворка пишет через него.
Телеметрия клиента получает ошибки логгера с категорией и шаблоном вместо текста (одна группа на место вызова, аргументы не
уходят) и марки `log.<level>`; бэкенд хранит категорию и учитывает её в fingerprint. BREAKING для клиента и протокола каждой игры.

## Шаги

### 1. `DebugOptions.EnableLogs` удалён (BREAKING)

Кого касается: клиент; на 2026-11-25 ни одна игра его не читает.
Поиск: `git grep -nE 'EnableLogs|_enableLogs' -- 'client/Assets/*.cs'`
Сделать: убрать обращения. Поле `_enableLogs` в `OptionsContainer.asset` Unity выбросит при следующем сохранении ассета.

### 2. Уровни логов в `OptionsContainer`

Кого касается: клиент каждой игры.
Сделать: Project Tools -> Options -> Log Options. По умолчанию development `Info`, release `Warning`, марки телеметрии выключены
(`None`). При желании правила по префиксу namespace или типа (`LogRule`: например `Global.Network` -> development `Debug`; марки
`Info` для категорий, которые нужны на таймлайне сессии), сохранить ассет. Применяет `OptionsContainer.Register` сам.
Подсказки профилировщика (`ProfilerTraceStorage`: «Trace saved… downloadProfilerTrace()») - `Info`: в release они нужны только
с правилом `Internal.ProfilerTraceStorage` -> release `Info`.

### 3. Протокол телеметрии: `SharedClientTelemetry.Error.Category` (BREAKING)

Кого касается: игры с тестами протокола (золотые файлы).
Поиск: `git grep -n 'SharedClientTelemetry+Error' -- '*.golden.txt'`
Сделать: новый последний член `Category` (`string`) у `Error`. Золотые файлы протокола игры (`protocol_schema.golden.txt`,
`protocol_bytes.golden.txt`, строки `Shared.SharedClientTelemetry+Error` и `+Batch`) перезаписать `UPDATE_PROTOCOL_GOLDEN=1`, хеш
протокола игры (`ProtocolHash`) поднять. Старый клиент с бэкендом нового релиза совместим (MemoryPack пишет число членов,
недостающая категория - `null`), но хеш держит клиентов одной сборки.

### 4. Все логи игры - через логгер (обязательно)

Кого касается: клиент каждой игры, весь код вне тестов (runtime и Editor). Шаг большой (десятки и сотни файлов): делается в этом же
обновлении, можно отдельными коммитами по сборкам; сборка и тесты - после всех.
Поиск: `git grep -lE 'Debug\.Log|UnityEngine\.Debug\.Log' -- 'client/Assets/*.cs' ':!*/Tests/*'`
Сделать: каждый вызов `Debug.Log` / `LogWarning` / `LogError` / `LogException` / `Log*Format` удалить и заменить логгером по
`tools/framework/.claude/docs/LOGGING.md`; после шага поиск находит только исключения ниже.
- Откуда лог: тип, который создаёт контейнер (регистрация в installer игры или фреймворка, MonoBehaviour с `[Inject]`), - параметр
  `ILog<T>` конструктора или `[Inject]`-метода (регистрации не нужно), поле `private readonly ILog _log`; тип, созданный через `new`
  (если ещё и тестами - те передают `Logs.Of<X>()`), struct, - `private static readonly ILog _log = Logs.Of<X>()`; статический класс -
  `Logs.Of(typeof(X))`.
- Текст: `Debug.Log($"[Game] [Run] Joined {code} in {ms:F1} ms")` -> `_log.Info("Joined {Code} in {Ms} ms", code, Math.Round(ms, 1))`:
  без ручных префиксов `[...]` (консоль пишет `[ИмяКласса]`), каждая интерполяция - плейсхолдер `{PascalCase}` с аргументом по порядку
  (0-4; больше - объединить или разбить строку), форматов `{x:F1}` нет, `$"..."` и конкатенации в шаблоне нет, фигурные скобки текста -
  `{{` / `}}`.
- Уровень: `LogWarning` -> `Warning`, `LogError` -> `Error`, `LogException(e)` -> `_log.Exception(e)`; `LogError` текста и следом
  `LogException` той же ошибки -> один `_log.Error(e, "текст", ...)`; `Log` -> `Info` для событий жизненного цикла (раз на сцену,
  сессию, забег), `Debug` для болтливого (на кадр, сообщение, пакет, колбэк).
- Тесты игры с `LogAssert.Expect` на эти тексты ждут новую строку `[ИмяКласса] текст`.
- Исключения, которые остаются на `Debug.Log*`: вызов с объектом-контекстом (`Debug.Log(text, gameObject)`, подсветка объекта в
  консоли редактора) и `Debug.Log` внутри своего `ILogSink`.
- Компилятор: поле класса с именем `Logs` закрывает статический класс - `global::Internal.Logs.Of<X>()`; `UAC0036` на
  `static readonly ILog` (автоочистка статиков Unity) - атрибут `[NoAutoStaticsCleanup]` на поле.

Только так ошибка игры приходит в телеметрию с категорией и шаблоном (одна группа на место вызова), а `Debug` вырезается из release.

### 5. Конструкторы типов фреймворка с логом (BREAKING)

Кого касается: тесты и инструменты игры, которые создают эти типы через `new`. Регистрации контейнера не меняются: лог даёт генератор.
Поиск: `git grep -nE 'new (SessionControl|SessionConnection|NetworkSession|NetworkObjectsCollection|EntityDestroyedCommand|NetworkLatencyMonitor|FrameRateLimit|AutoFrameRate|RenderResolution|ClientOutdatedNotice|MatchMetrics|MatchMetricsSocketTransport|TelemetryHttpTransport|TelegramDebugAPI|SteamInvites|SteamPlatformAchievements|SteamPlatformInventory|UnitySessionLog)\(' -- 'client/Assets/*.cs'`
Сделать: последним аргументом `Logs.Of<X>()` (у `UnitySessionLog` - любой `ILog`, первым и единственным). Пример:
`new SessionConnection(connection)` -> `new SessionConnection(connection, Logs.Of<SessionConnection>())`; тесты фреймворка
(`SessionConnectionTests`, `PeerMeshTests`, `NetworkObjectsCollectionTests`) - образец.

## Проверить поведение

- Строки фреймворка в консоли: `[ИмяКласса] текст` вместо `[Network] [Session] ...`; тесты игры с `LogAssert.Expect` на тексты
  фреймворка ждут новые строки (`[SoundPool] ...`, `[ConnectionWriter] ...`, `[NetworkLatencyMonitor] ...`).
- В release-плеере `Info` фреймворка по умолчанию не пишется (уровень `Warning`), `Debug` не скомпилирован (нужен - `FRAMEWORK_LOG_DEBUG`).
  В player-сборках строки ниже `Warning` идут без стека.
- Ошибки фреймворка в телеметрии: с категорией, сообщение - шаблон (`Lost the room {Code}`); исключение - шаблон, `\n`, `Тип: текст`
  и свой стек. Ошибки Unity и стороннего кода - как раньше, без категории. Строки `UnitySessionLog` (`SessionCore`) и libdatachannel
  (`NativeWebRtcLibrary`) приходят шаблоном `{Message}` / `{Line}`: одна группа на категорию.
- `ReactiveExceptions` пишутся категорией `Internal.ReactiveExceptions`.

## Без действий

- Бэкенд телеметрии: `category` в строках `/sessions/{id}/errors`, в группах дайджеста и `/errors`, рядом с уровнем в консоли;
  категория не в виде имени типа или длиннее 256 отбрасывается, ошибка остаётся. Fingerprint без категории прежний.
- Скрабберы клиента и сервера оставляют плейсхолдер `{Identifier}` (до 31 символа); корпус PII дополнен.
- Скилл `client-telemetry` печатает `[Category] template`, знает марки `log.*`.
- `LOGGING.md`, строка в `INDEX.md`, раздел Logging в `CLAUDE.md`.
- `Logs.AddSink(lifetime, ILogSink)` для своих приёмников записей.
