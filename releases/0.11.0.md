# 0.11.0

20 commits (`v0.10.0..3fd04fed`): the content code in the core is laid out by role (`Runtime/Content`: `Common`, `Loading`, `Sources`,
`Storage`, `Distribution`; `Editor/Content`: `Steps`, `Layout`, `Pipeline`, `Output`, `Player`, `Definitions`, `PlayMode`), the types are
renamed after what they do; there are three public renames a game sees (steps 1-3). A new phase of the content build
`IContentLayoutStep`: in it the `ContentRoot` of the build without the bundles left out of the build. `update-framework` offers the shared skills
the game has no link to.

## Steps

### 1. Content: `ContentLoader.Register` -> `ContentEntryPoint.RegisterMain` (BREAKING)

Who: the client of games that register the main bundle without a scope (a smoke player, a tool). On 2026-11-18 there are none; in
the framework only `client/project/Assets/ContentSmoke/ContentSmokeProbe.cs`.
Search: `git grep -n 'ContentLoader.Register' -- 'client/*.cs'`
Do: `ContentLoader.Register(lifetime, options)` -> `ContentEntryPoint.RegisterMain(lifetime, options)` (the same arguments, the same
`UniTask<ContentLoader>`); without it CS0117. A game with scopes calls `AddContent`, as before.

### 2. Content: `IContentBundles` -> `IContentLoadersCollection` (BREAKING)

Who: the client of games that take the bundle loaders of `AddContentBundle` from the root scope: storytale-workshop
(`BuiltInBooks`, `Wait`), gamejam-autobattler (`MenuMusic` - `Wait`, `BattleViews` - `Get`, `Wait`).
Search: `git grep -nw IContentBundles -- 'client/Assets/*.cs'`
Do: `IContentBundles` -> `IContentLoadersCollection` in fields, constructors and `[Inject]` (the same methods: `Get(name)`,
`Wait(lifetime, name)`); without it CS0246. `AddContent` registers the registry under the new interface, the class `ContentBundles` ->
`ContentLoadersCollection` (the generated container of the root updates itself on compilation).

### 3. Client: `ScopeLoadOptions.SceneLoader` -> `ServiceScene` (BREAKING)

Who: the client of games that read the scene of the scope options (tests of scope loaders, own `IServiceScopeLoader`s):
gamejam-autobattler (`ScopeScenesTests`). The name was the same as `IScopeBuilder.SceneLoader` (`ServiceScopeSceneLoader`, the scene loader
inside a scope), though this is the scene of the scope itself (`NoScene`, `RuntimeScene`, `ContentAssetScene`).
Search: `git grep -nE '\.SceneLoader\b' -- 'client/Assets/*.cs'` (leave the uses of `IScopeBuilder.SceneLoader`)
Do: `options.SceneLoader` -> `options.ServiceScene`; without it CS1061.

## Check the behaviour

- A build that leaves bundles out of the build (`build.Exclude`, `Stress` in pixel-swarm, `Tools` in storytale-workshop): the `ContentRoot` without
  the roots of these bundles is now written by `ContentRootBuildStep` in the phase `IContentLayoutStep` (`BeforeLayout`), the full one comes back in
  `AfterBundles`, also after a failed build. The result is the same as before; to notice: after the build `ContentRoot.asset` has no changes in git.
