## Шаги

### 1. Контент: `ContentLoader.Register` -> `ContentEntryPoint.RegisterMain` (BREAKING)

Кого касается: клиент игр, которые регистрируют главный бандл без скоупа (смоук-плеер, инструмент). На 2026-11-18 таких нет; во
фреймворке только `client/project/Assets/ContentSmoke/ContentSmokeProbe.cs`.
Поиск: `git grep -n 'ContentLoader.Register' -- 'client/*.cs'`
Сделать: `ContentLoader.Register(lifetime, options)` -> `ContentEntryPoint.RegisterMain(lifetime, options)` (те же аргументы, тот же
`UniTask<ContentLoader>`); без этого CS0117. Игра со скоупами зовёт `AddContent`, как раньше.

### 2. Контент: `IContentBundles` -> `IContentLoadersCollection` (BREAKING)

Кого касается: клиент игр, которые берут загрузчики бандлов `AddContentBundle` из корневого скоупа: storytale-workshop
(`BuiltInBooks`, `Wait`), gamejam-autobattler (`MenuMusic` - `Wait`, `BattleViews` - `Get`, `Wait`).
Поиск: `git grep -nw IContentBundles -- 'client/Assets/*.cs'`
Сделать: `IContentBundles` -> `IContentLoadersCollection` в полях, конструкторах и `[Inject]` (методы те же: `Get(name)`,
`Wait(lifetime, name)`); без этого CS0246. `AddContent` регистрирует реестр под новым интерфейсом, класс `ContentBundles` ->
`ContentLoadersCollection` (сгенерированный контейнер корня обновится сам при компиляции).

### 3. Клиент: `ScopeLoadOptions.SceneLoader` -> `ServiceScene` (BREAKING)

Кого касается: клиент игр, которые читают сцену опций скоупа (тесты загрузчиков скоупов, свои `IServiceScopeLoader`):
gamejam-autobattler (`ScopeScenesTests`). Имя совпадало с `IScopeBuilder.SceneLoader` (`ServiceScopeSceneLoader`, загрузчик сцен
внутри скоупа), хотя это сцена самого скоупа (`NoScene`, `RuntimeScene`, `ContentAssetScene`).
Поиск: `git grep -nE '\.SceneLoader\b' -- 'client/Assets/*.cs'` (оставить обращения к `IScopeBuilder.SceneLoader`)
Сделать: `options.SceneLoader` -> `options.ServiceScene`; без этого CS1061.

## Проверить поведение

- Сборка, которая оставляет бандлы вне сборки (`build.Exclude`, у pixel-swarm `Stress`, у storytale-workshop `Tools`): `ContentRoot` без
  корней этих бандлов теперь пишет `ContentRootBuildStep` в фазе `IContentLayoutStep` (`BeforeLayout`), полный возвращается в
  `AfterBundles`, и после неудачной сборки тоже. Результат прежний; заметить: после сборки `ContentRoot.asset` в git без изменений.

## Без действий

- `IContentLayoutStep` (`BeforeLayout` / `AfterBundles`) и `ContentBuildContext.ExcludedBundles`: шаг игры, которому нужен
  окончательный набор бандлов вне сборки (после всех `IContentBuildStep` и общих бандлов). `Exclude` после всех `IContentBuildStep`
  бросает.
- Переименования внутри контента, которые игры не используют (поиск по HEAD всех пяти игр пуст): записи каталога
  `ContentCatalog*Entry` (формат `catalog.json` и `CurrentVersion` те же), `ContentBundleSet` -> `ContentBundleStorage`,
  `IContentBundleStore` / `Local|WebContentBundleStore` -> `IContentDistribution` / `Local|WebContentDistribution`,
  `ContentCatalogPaths` -> `ContentShippedPaths`, `ContentLoads` -> `ContentLoadsCollection` (методы вместо публичных словарей), и типы
  раскладки и сборки редактора (`ContentOwnership`, `ContentAssetOwner`, `ContentLazyReferenceScanner`, `ContentBuildTargetSelection`,
  `ContentUnsavedScenes`, `ContentPlayerStamp`). Файлы перенесены с `.meta`, GUID сохранены (скрипт `ContentBundle` тоже), namespace
  `Internal` прежний. `IContentBuildStep`, `ContentBuildContext`, `IContentSharedBundles`, `ContentBuild` - те же имена и члены, лежат в
  `Editor/Content/Steps`, `Editor/Content/Shared`, `Editor/Content`.
- jslib веб-загрузки (`WebContentFetch.jslib`, `WebContentQueue.jslib`) лежат в `Runtime/Content/Distribution/Web`, импорт тот же.
- Тесты: общая загрузка файла бандла живёт, пока её ждёт хоть одна загрузка; `ContentRoot` сборки без бандла.
- Скилл `update-framework`: `status.sh` перечисляет общие скиллы без ссылки в игре (и копии вместо ссылок, битые ссылки), шаг 6
  предлагает их привязать; отказ записывается в `.claude/project-skills.md` § update-framework как `` Not linked: `<name>` ``.
- `CONTENT.md`: раскладка кода контента (Code layout), фаза `IContentLayoutStep`, новые имена; ожидаемые числа `test-all.sh`.
