### The Roslyn analyzers of the code rules come in the client: FWR001-FWR006 as warnings

Who: every game, client and backend. `client/core/Analyzers/Framework.Analyzers.dll` (label `RoslynAnalyzer`, next to
`ContainerGenerator.dll`) is given by Unity to every assembly of the game: after the pointer moves the Unity compile and `dotnet build`
of `client.sln` print `warning FWR00N` (public setters, files above 300 lines, several top-level types, Cyrillic in comments, `lock` on a
lifetime, a file not named after its type). Warnings only: nothing stops compiling. The rules and the settings:
`client/core/Source~/Analyzers/README.md`.

Search: `ls client/Packages client/Assets/Plugins; git grep -ln 'Auto-generated by' -- 'client/Assets/*.cs' | head`

Do:
- Third-party code gets no rule when it is under `Library/PackageCache`, a package folder of `client/Packages` (or the forks in
  `tools/framework/client/packages`) or `Assets/Plugins`. Unity reads no `.editorconfig`, so third-party code anywhere else in
  `client/Assets` is moved under `Assets/Plugins` (or marked `framework_rules.third_party = true` in `.editorconfig`, which only
  `dotnet build` honours). Nothing to add for the packages.
- Regenerate the generated code of the framework (`Tools/Framework/Codegen/Regenerate All`, `-executeMethod Internal.RegenerateAll.Run`):
  the generators now write `// <auto-generated/>` as the first line, before `// Auto-generated by X`; until a file is
  regenerated the rules see it as code of the game (mines-leader before it: 8 findings in `Catalogues/Colors/Colors.cs` and
  `Catalogues/Sprites/CardsIconsSprites.cs`). After it the search above lists only files with the new header first.
- Backend: add the same dll to `backend/Directory.Build.props` (or the props every backend project imports) and build
  `backend/backend.slnx`:
  `<ItemGroup><Analyzer Include="$(MSBuildThisFileDirectory)../tools/framework/client/core/Analyzers/Framework.Analyzers.dll" /></ItemGroup>`
  (the path is relative to the props file). The settings of `.editorconfig` apply there: a rule a game is not ready for is
  `dotnet_diagnostic.FWR00N.severity = none`, a rule whose findings are gone may become `error` (in the Unity compile it stays a warning).
- Count the findings to plan the cleanup: `dotnet build client/client.sln -v:minimal | grep -oE 'warning FWR[0-9]+' | sort | uniq -c`
  (each warning is printed twice, divide by two).
