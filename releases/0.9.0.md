### 1. Content: `IContentBuildStep.BeforeContentBuild(ContentBuildContext)`, bundles left out of a build (BREAKING)

Who: the client of games with their own `IContentBuildStep`, and of games that need part of their content not in every build (pixel-swarm: Stress).

Search: `grep -rn "IContentBuildStep\|BeforeContentBuild" client/Assets --include='*.cs'`

Do:
- `public void BeforeContentBuild()` -> `public void BeforeContentBuild(ContentBuildContext build)`; without it CS0535.
- A bundle that must not be in the build is left out by a step: `if (<not this build>) build.Exclude("Stress");` (`build.Target` is the platform,
  the profile is `BuildProfile.GetActiveBuildProfile()`). It is absent from the bundles, the catalog and the `ContentRoot` of this build, the asset stays in the project;
  a reference of a built bundle to what it holds is a build error (`... held by the content bundle Stress, which this build leaves out`).
  pixel-swarm: the step of `PLATFORM_STRESS` of the profile, as `StressBuildStep` with the Addressables group before, instead of the workaround with the Stress bundle in
  every build; check that website and telegram build without Stress, and web_stress with it.

### 2. Content: the shared bundles of a game - `IContentSharedBundles` instead of an own sync

Who: the client of games that write the shared bundles themselves, parsing the text of the layout errors (pixel-swarm `ContentSharedRoots`).

Search: `grep -rln "ContentBundleLayout.Lay\|is needed by the content bundles" client/Assets --include='*.cs'`

Do:
- Delete the own sync and its `IContentBuildStep` (pixel-swarm: `ContentSharedRoots.cs`, `ContentSharedRootsStep.cs` and the menu item
  `Tools/Game/Content/Sync Shared Bundles`); its calls (`LocationLevel` and others) go to `ContentSharedSync.Run()`.
- One editor class of the game: `IContentSharedBundles { Folder; Bundles }` - the folder of the game with the assets of the shared bundles and an ordered list
  `new ContentSharedBundle(name, isPreloaded, isGzip, params serves)`. pixel-swarm: `Folder` is `Assets/Common/Internal/Editor/Content`,
  `SharedCommon` (preloaded, serves `Main`), `SharedLobby` (gzip, serves `Lobby`), `SharedGamePlay` (gzip, no list - the rest).
  The sync runs before every content build (after the steps), in Regenerate All and from Tools/Framework/Codegen/Sync Shared Content Bundles.
- Check: Sync Shared Content Bundles changes no file (the roots are the same as the own sync wrote); the build has no layout errors.
- The layout returns its errors as data: `ContentBundleLayout.Inspect(bundles, excluded)` - `Duplicates` (path, bundles), `Errors`, without
  an exception; for own tools instead of parsing the text of `BuildFailedException`.

### 3. Content: a dirty scene stops the build with a clear error

Who: games whose tests or tools build the content (`ContentBuild.Prepare` / `Build`, `ContentBundleBuilder.Build`).

Search: `grep -rn "ContentBuild.Prepare\|ContentBuild.Build\|ContentBundleBuilder.Build" client/Assets --include='*.cs'`

Do: nothing required. The build throws `The open scenes ... have unsaved changes` before SBP (before: the return code `UnsavedChanges`);
an own test that builds opens a new scene before the build and restores the scenes after it (as `ContentTestScenes` of the framework tests do),
and before it creates bundles in memory: the new scene destroys them. The framework tests `ContentBuildTests` in a run of the game no longer fail because of
a scene left by other tests.
