# Framework.Analyzers

Roslyn analyzers of the code rules of the framework docs (`CODE_STYLE_FULL.md`, `ARCHITECTURE_PRINCIPLES.md` P6, P11). Every rule is
a warning by default. Same Roslyn API as ContainerGenerator (`Microsoft.CodeAnalysis.CSharp` 4.3.0, netstandard2.0): Unity loads it.

| Id | Rule | Notes |
|----|------|-------|
| FWR001 | public setter or public mutable field | a public member of an internal type counts, of a private nested type does not; allowed: `[MemoryPackable]` types (and their nested types), public fields of a `[Serializable]` type without methods or operators (JsonUtility data), Blazor `[Parameter]` / `[CascadingParameter]` / `[SupplyParameterFromQuery]` / `[SupplyParameterFromForm]`, members of an attribute class, `override`, an implementation of an interface property with a setter (an interface of the sources is reported on its own declaration) |
| FWR002 | file above 300 lines | runtime and editor code only, see "Code kind"; lines as `wc -l` counts them |
| FWR003 | more than one top-level type in a file | allowed together: `IX` + `X` + `XExtensions`; the parts of a partial type and the generic variants of one name (`Option`, `Option<T>`) are one type; nested types do not count; tests count |
| FWR004 | Cyrillic in a comment | `//`, `/* */`, `///`, `/** */`; strings are not comments |
| FWR005 | `lock` on a lifetime | the type is `Internal.IReadOnlyLifetime` or implements it (a type parameter by its constraints); allowed only inside `Internal.Lifetime`; skipped without `Framework.Common` |
| FWR006 | file not named after its type | the name up to the first dot (`X.Host.cs` is a part of `X`) is one of the types of the file |

Generated code is skipped by Roslyn: a file `*.g.cs`, `*.generated.cs`, `*.designer.cs`, a first comment with `<auto-generated`, or
`generated_code = true` for its path in `.editorconfig` (dotnet build only, see below). The generators of the framework (catalogues,
hierarchy bindings, the container asset map) write `// <auto-generated/>` as the first line, before their own
`// Auto-generated by X` line; a file written by an older framework keeps only the second one and is analysed until it is regenerated.

## Third-party code

Every rule skips third-party code: a path with a folder `PackageCache` (`Library/PackageCache`, the registry packages), a package
folder (a name with a dot, `com.x.y`) inside a folder `Packages` / `packages` (the embedded packages of a game in `client/Packages`, the
forks of the framework in `client/packages`), or `Assets/Plugins`. `framework_rules.third_party = true` / `false` of `.editorconfig`
wins over the path (any other value throws).

Why the path and not `.editorconfig` alone: Unity passes no `.editorconfig` to its compiler. Its response files
(`Library/Bee/artifacts/*.dag/<Assembly>.rsp`) hold `-analyzer:` and, for the immutable packages only, `-ruleset:` with
`Library/ImmutablePackage.ruleset`, but no `-analyzerconfig:`, even with `client/.editorconfig` at the root of the project. So in the
Unity compile no option of this file is read: the severities, `framework_rules.*` and `generated_code` work in `dotnet build` of the
generated csproj (MSBuild finds the `.editorconfig` files above every source), and the Unity compile has the defaults: every rule a
warning, the limit 300, the code kind and the third-party code by the path. A game that has third-party code elsewhere moves it under
`Assets/Plugins` or a package.

## Code kind

FWR002 skips tests and benchmarks. A file is a test or a benchmark when:
- `framework_rules.code_kind` of `.editorconfig` for its path is `test` or `benchmark` (any other value, `runtime`, makes it runtime code
  and wins over the next two);
- its assembly name ends with `Tests`, `Benchmarks`, `.TestTools`, `.Tests.Fixtures` or `.Verify` (`Internal.Tests`,
  `Internal.Network.PlayMode.Tests`, `Benchmarks`);
- a folder of its path is `Tests`, `Tests~`, `Test`, `Benchmarks` or ends with `.Tests` / `.Benchmarks` (a folder `Benchmark` of the
  console is runtime code).

## Settings of a game

Read by `dotnet build` only (Unity ignores `.editorconfig`, see "Third-party code"):

```ini
[*.cs]
dotnet_diagnostic.FWR004.severity = none      # a rule off, or error when its findings are gone
framework_rules.max_file_lines = 300          # FWR002 limit

[Assets/Vendor/**.cs]
framework_rules.third_party = true            # third-party code outside Plugins and packages: no rule at all

[Assets/Common/Internal/Runtime/Catalogues/**.cs]
generated_code = true                         # generated code without the <auto-generated/> header
```

## Build and tests

```
dotnet build client/core/Source~/Analyzers.Verify/Analyzers.Verify.csproj
.build/bin/Analyzers.Verify/Debug/net10.0/Analyzers.Verify          # ALL PASSED <n>, exit code 1 on a failure
dotnet build client/core/Source~/Analyzers/Analyzers.csproj -c Release -p:CopyToAnalyzers=true
```

Only the last command writes `client/core/Analyzers/Framework.Analyzers.dll` (committed with its `.meta`); the dll there turns the rules
on in every game, so a plain build leaves it out. After a change of the rules: run the tests, then the Release build, and commit the dll.
Its `.meta` is the one of `ContainerGenerator.dll` with a new guid: label `RoslynAnalyzer`, every platform off. Unity gives it to the same
assemblies as `ContainerGenerator.dll` next to it (mines-leader, 2026-11-25: all 116 assemblies of the Unity compile, 84 of the 101
projects of `client.sln`). The backend adds the same dll in its
`Directory.Build.props`: `<Analyzer Include="$(MSBuildThisFileDirectory)../tools/framework/client/core/Analyzers/Framework.Analyzers.dll" />`
(or a `ProjectReference` to `Analyzers.csproj` with `OutputItemType="Analyzer" ReferenceOutputAssembly="false"`).
